# Rune

Rune is an AI-native workspace for documents, data, and presentations. It keeps Markdown, CSV/JSON, DuckDB SQL, declarative Chart JSON, and Deck Markdown as readable source, then renders each artifact live in one focused workbench. Legacy semantic HTML decks remain import-compatible.

## Status

The project has a working local-first vertical slice: human- and Agent-initiated creation across all five canonical artifact modes, Rune-owned action-local creation handles for one-transaction Data → Query → Chart → Markdown/Deck workflows, explicit source/field binding, a source-derived workspace dependency graph, graph-bounded and user-pinned model context, bounded current-Query evidence for configured Workspace models, runtime-verified Agent Data/SQL/Chart impact with one bounded compiler-guided model repair, keyed row and column operations for CSV/flat JSON, reusable bar and line Chart bindings with cross-runtime deterministic number formatting, browser-local SQL with proof-safe result lineage and explicit multi-Data source binding, revision-bound Query-backed charts and scalar metrics, semantic Office Open XML import/export, portable standalone Deck HTML, direct fixed-layout PDF export for Documents and Decks, persistent device checkpoints, section/row/cell/slide preview targeting, cross-artifact chart/query-to-cell provenance, artifact-aware and selection-confined Agent operations, reviewable atomic workspace changes, and explicit sync with user-owned source folders. Product reasoning lives in [`idea.md`](idea.md), architectural contracts in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), and one-line milestones in [`PROGRESS.md`](PROGRESS.md).

## Development

```bash
npm install
npm run dev
```

Then open the local URL printed by the development server.

Rune always includes deterministic local planners for selection, file, and workspace actions. To enable model-generated reviewable changes, copy `.env.example` to `.env.local`, set `OPENAI_API_KEY` in that local file, and optionally choose `OPENAI_MODEL`. Keys stay server-side and must never be committed. Instead of resending whole files, the model returns at most eight typed operations per file: replace or insert a Markdown section by heading; upsert one typed CSV/flat-JSON row by unique key; add or update a typed column through exact keyed values; rename one exact non-colliding column; replace or insert a Deck slide by title; append one exact live Chart to Markdown/Deck; or use an exact `find → replace` fallback for precise inline and structural edits. A workspace plan contains at most four `patch_artifact` or `create_artifact` actions. Every creation has a short action-local handle; Query and Chart sources may reference either an exact visible artifact or a handle declared by an earlier creation. Handles are ordered capabilities, not filenames or ids: Rune resolves collisions, compiles them into real canonical references, and strips them from the review result. Forward, duplicate, wrong-kind, missing, or guessed-id references fail the complete plan. Rune still owns ids, filenames, extensions, language metadata, complete starter source, and every state write. Nothing is written unless the captured source revision is current, the complete next workspace validates, every affected Query-backed Chart passes local runtime preflight, and every changed existing file has a safety checkpoint.

Selecting text in the source editor automatically exposes the **Selection** Agent scope. Rune binds the request to that artifact revision and its exact UTF-16 source offsets, limits the selected context to 16,000 characters, and proves after operation compilation that the complete prefix and suffix are byte-for-byte unchanged. The client repeats the same confinement check before Apply, then uses the normal concrete diff, checkpoint, adapter validation, dependency validation, and atomic persistence path. A stale, collapsed, oversized, or Unicode-splitting range is rejected without changing the workspace.

The live preview can create that same exact context without guessing from rendered DOM. Choosing a rendered Markdown section from its preview outline, clicking a non-empty CSV/JSON cell, choosing a data row number, activating a provably direct SQL result field, or choosing a Deck slide above the sandboxed presentation maps the visible object back to a deterministic range in canonical source, focuses that range in the editor, and activates Selection scope. A cell selects its complete source token, including CSV quotes or JSON string delimiters, while a row number selects the full record. Markdown fences, quoted multiline CSV records, escaped quotes, nested JSON values, missing fields, Deck frontmatter, and slide separators are handled locally. Ambiguous duplicate JSON keys expose only their unambiguous full row; computed SQL cells, aggregates, multi-source results, and legacy HTML stay read-only until Rune can prove an exact mapping.

Charts carry field-level provenance across artifact boundaries. A Chart can read canonical Data directly or consume the current result of a Query, using a categorical bar or ordered line mark. Direct-data marks retain their exact row and category/value cells; Query-backed marks preserve exact canonical cell targets only for direct projected fields, while calculated fields stay read-only. Duplicate labels never require fuzzy matching. Clicking or keyboard-activating a provable label plus its bar or line point switches to the underlying CSV/JSON artifact and enters the same confined Agent flow. Static Deck/HTML/Office/PDF snapshots remain non-interactive handoffs, and a mark stays read-only when its current source cannot produce an exact cell target.

The **Data graph** activity shows the current source-to-consumer topology rather than a manually maintained diagram. Rune recompiles legacy metric, `workspace_data`, Query-to-scalar-metric, Data-to-Chart, Query-to-Chart, and chart-embed edges from every current artifact revision, exposes unresolved intent, and makes both `Data → SQL → metric → Document/Deck` and `Data → SQL → Chart → Document/Deck` navigable. A Query with `-- rune:data "artifact-id"` contributes an edge from that exact Data artifact, so folder or manifest reordering cannot silently change its input. The same graph selects an upstream-closed Workspace Agent context: only components rooted at the selected artifact or an explicit pin are considered, at most seven files and 180,000 source characters are sent, and original workspace order preserves the remaining legacy first-Data semantics. A pin control beside each file lets the user deliberately bridge bindings the source cannot express—for example, coordinating two independent Markdown briefs—without persisting a hidden relationship; up to six pins last only for the current session and each pulls in its required upstream sources. The server independently recompiles supplied edges and rejects any disconnected file not explained by the selection or a pin before model work. The deterministic fallback receives that same pack, while the complete device workspace is still revision-checked and validated before Apply. Large or incomplete context falls back locally instead of dropping a pin or broadening model access.

When that verified Workspace context contains Query artifacts, a configured provider receives runtime evidence through a two-step handshake. The first request sends sources and graph identities only; after the server confirms that a provider exists, it asks the browser for the exact Query ids it needs. Rune then runs those Queries locally against their resolved Data revisions and retries once with at most 20 rows, 32 columns, 400 cells, 500 characters per string, and 20,000 JSON characters across the evidence pack. Runtime errors are returned as bounded feedback instead of being disguised as results. Evidence is advisory, can be truncated, is never persisted, and is available only in Workspace scope where those canonical Query and Data sources already passed the graph boundary. With no configured provider Rune returns the local fallback immediately and does not start DuckDB merely for model context.

Any Agent plan that changes Data, SQL, or Chart source—provider-backed or deterministic, in Selection, File, or Workspace scope—must pass a second local boundary before its diff can appear. Rune constructs the complete proposed workspace in memory, finds every Query bound to proposed Data, every directly changed Query, and every Query selected by a changed or newly created Chart, then executes that impact set against exact proposed revisions. It verifies affected legacy metrics, Query scalars, direct-Data Charts, and Query-backed Charts. A disconnected new Data source or direct-Data Chart never runs unrelated SQL. If a configured model's first concrete proposal fails, Rune may send that unapplied proposal plus a bounded compiler error back to the same model exactly once, using the unchanged canonical request and any already-verified Query evidence. The response must be a complete replacement operation plan and pass the server compiler plus the same full local impact graph again. Only that successful replacement becomes reviewable, clearly labelled as repaired once; failed feedback construction, transport, response validation, or second preflight stops with no local fallback and changes no source, checkpoint, folder, or device state. Deterministic local plans never enter this repair path. Canonical source, Rune's compilers, explicit review, and the captured revision remain the authority.

**New** starts any canonical artifact without first creating a file elsewhere. Document, Data, and Presentation retain their minimal Markdown, two-column CSV, and one-slide Deck templates. Query requires an explicit Data selection and writes a readable first-line `-- rune:data` identity plus `SELECT * FROM workspace_data`; Chart requires an exact Data/Query source, category/value fields, bar/line mark, and number format, then writes complete strict Chart JSON. Numeric Data fields are surfaced as defaults without hiding the exact source choice. A new Chart can optionally be embedded in a selected Markdown report or Deck during the same confirmation: Rune creates the reusable Chart, appends one readable binding, checkpoints the changed consumer, validates the complete graph, and performs one device write. Workspace Agent can now express the same dependency chain with ordered symbolic handles; the no-key quick command `根据收入数据创建分析、图表和报告` prepares a bound Query, live Chart, and linked report in one review transaction. Invented fields, foreign sources, guessed or forward identities, runtime-invalid values, or storage failure produce no partial file.

Opening a `.sql` artifact lazily downloads a version-pinned DuckDB-Wasm runtime. Its optional first non-empty line, `-- rune:data "artifact-id"`, binds `workspace_data` to one exact CSV/JSON artifact; imported older SQL without the directive keeps a visibly labelled first-Data fallback. Rune materializes that resolved parser output in exact source order, then runs the query entirely in the browser. For a conservative single-table, row-preserving `SELECT`, Rune carries an internal source-row identity through filters, sorting, aliases, and limits: direct projected columns and result row numbers can open the exact CSV/JSON token or record, while calculated fields remain visible but non-targetable. `WITH`, aggregate, `DISTINCT`, grouping, JOIN, set, pivot, sampling, window, or row-expanding query shapes still run but expose no edit capability. A Chart may name the Query artifact as its source; Rune infers a conservative output schema for workspace validation, waits for a snapshot bound to the exact Query and resolved Data revisions, and refuses missing, mismatched, stale, or truncated results. Documents and Decks may likewise bind a numeric scalar with `{{ metric("query-id", "output-column", "currency|number|percent") }}`. A scalar compiles only from the current non-truncated Query/Data snapshot, exactly one result row, an unambiguous output column, and a finite numeric value; static schema drift or runtime cardinality/type drift fails closed. The hosted app needs no database for this workflow.

Chart artifacts use a bounded `.chart.json` schema that names an existing Data or Query artifact, exact category/value columns, and either a `bar` or `line` mark. Bar compares categories; line preserves the explicit source/value sort as an ordered series and normalizes negative, flat, or positive finite values without inventing data. Query-derived fields must have explicit `AS` aliases so the output contract remains reviewable without executing SQL during every edit. The same `{{ chart("artifact-id") }}` reference compiles into a React chart inside Markdown and escaped static HTML inside the sandboxed slide runtime; schema drift blocks the whole pending workspace transaction.

Visible metric, chart, count, and export numbers use a Rune-owned formatter instead of runtime-dependent compact `Intl.NumberFormat` output. Grouping, compact suffixes, signs, rounding, and trailing-zero removal are therefore identical in the Cloudflare server render, browser hydration, live React preview, sandboxed Deck HTML, and frozen Office/PDF output. This avoids turning a harmless engine-level locale difference such as `$970K` versus `$970.00K` into a React hydration failure.

Presentation source uses a bounded `.deck.md` grammar: strict versioned frontmatter, `---` slide separators, controlled layout and eyebrow metadata, and a small set of Markdown blocks. Rune rejects raw HTML, escapes user text, owns layout and numbering, then compiles the source into a scriptless sandboxed HTML runtime. The same compiler can freeze the current metrics and charts into a downloadable single-file presentation. Legacy and Query-backed metric references plus chart references stay readable in the deck source; legacy `.html` presentations still open through the same sandboxed compatibility path.

**Import** accepts modern `.docx`, `.xlsx`, and `.pptx` files without uploading them. A lazily loaded browser converter maps DOCX structure to Markdown, each visible XLSX worksheet to a separate CSV artifact, and ordered PPTX text/tables to Deck Markdown that immediately compiles to HTML. The contract targets semantic fidelity: images, comments, slide charts, complex styling, macros, and legacy binary `.doc/.xls/.ppt` are not silently guessed. Rune validates the complete batch and resolves collisions, then opens a keyboard-accessible review with every generated filename, a bounded source preview, and all omission warnings. Only explicit confirmation performs the single device write; cancel, stale workspace context, validation failure, or storage failure leaves the current workspace unchanged.

**Office export** performs the reverse compatibility handoff without changing canonical source. Markdown becomes semantic DOCX, CSV/JSON becomes a values-only XLSX worksheet, and Deck Markdown becomes a 16:9 PPTX with ordered text, bullets, tables, a slide master, layout, and Rune theme. Workspace metrics are compiled before packaging; every referenced Query is rerun against its exact Data revision so scalar values and Query-backed charts freeze the same current evidence into the package. A referenced bar Chart becomes a selectable semantic bar table in DOCX; a line Chart becomes a semantic trend table; PPTX receives editable native text and vector bar/line geometry. Image and runtime features that still cannot be represented are called out rather than guessed. Every package is deterministic, generated locally with standard OOXML parts, and held behind the same keyboard-accessible fidelity review before one browser download. The original `.md`, `.csv/.json`, and `.deck.md` download remains available beside it.

**Standalone HTML export** turns a Deck Markdown artifact into one portable, scriptless `.html` file. It resolves legacy metrics, reruns every Query referenced by a scalar metric or Chart, and freezes those values and views before export; the result embeds all styling, contains no external resources, and adds print rules that place each 16:9 slide on its own page for browser PDF handoff. The deterministic file is capped at 2 MB and uses the same stale-context check and explicit review-before-download transaction as Office export.

**Direct PDF export** creates the final handoff without a print dialog or hosted renderer. Markdown Documents become paginated A4 files with semantic headings, paragraphs, lists, quotes, code, tables, page numbers, and vector Chart snapshots. Deck Markdown becomes one fixed 16:9 PDF page per slide with Rune layout, scalar metrics, tables, and vector Chart snapshots. Rune reruns every referenced Query against its exact Data revision, embeds a bundled Unicode font so text does not depend on a network or receiver font, fixes document metadata for byte-deterministic output, and exposes all fidelity limits before confirmation. The PDF contains no JavaScript, forms, external resources, live bindings, or editable source structure; it is capped at 12 MB and leaves the canonical workspace unchanged.

On browsers that implement the File System Access API, **Open folder** connects Rune to real source files plus a readable `rune.workspace.json` manifest. Pull validates the complete folder and checkpoints every current artifact before replacing device state; explicit Query bindings keep SQL inputs stable even when manifest order changes. Push is always explicit, overwrites only matching artifact names after confirmation, and leaves unrelated files untouched. The handle is intentionally session-scoped; regular import and per-file download remain available as fallbacks.
