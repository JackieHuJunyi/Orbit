# Rune

Rune is an AI-native workspace for documents, data, and presentations. It keeps Markdown, CSV/JSON, DuckDB SQL, declarative Chart JSON, and semantic HTML as readable default source, then renders each artifact live in one focused workbench. Existing Deck Markdown remains supported as an explicit typed compatibility format.

Rune v1.46 makes full-workspace reset a reviewed, recoverable device operation instead of an immediate destructive shortcut. “Restore sample workspace” now lives in the low-frequency More Tools menu and opens a lazy nine-language review that compares current and target file/history/task facts, lists bounded target filenames, focuses Cancel first, and explains that connected folders remain untouched. A React-free planner captures exact current and target snapshots, rejects malformed, duplicate, unchanged, or oversized state, and rechecks both snapshots on confirmation. One localStorage transaction writes the target workspace together with the complete current workspace as `resetRecovery` before React advances. “Restore previous workspace” swaps those snapshots, making recovery itself reversible across reloads; cancellation, stale state, changed recovery, or storage failure writes nothing. The newly deferred Settings surface also keeps the minified Workbench at 527,660 bytes under its unchanged 530 KB gate. The release is covered by 664 unit, 28 render/architecture, and 53 Chromium tests. See [ADR 0062](docs/decisions/0062-workspace-reset-is-a-recoverable-device-swap.md).

## Development

```bash
npm install
npm run dev
npm run eval:golden
```

Then open the local URL printed by the development server.

On macOS, `npm run desktop:dev` builds and launches the current Rune desktop shell. It protects the existing personal-model vault master key with Electron `safeStorage` and the macOS Keychain; neither the key nor Node access enters the renderer. Legacy `.doc` and `.ppt` import uses an installed Microsoft Word or PowerPoint locally, with Office automation macros forced off, a 12 MB input ceiling, a 30-second conversion limit, private temporary files, and the same fidelity review before anything enters the workspace. Document and Deck export can also compile the current canonical source to Rune's verified DOCX/PPTX package, then make a reviewed local DOC/PPT compatibility handoff through installed Office under the same limits. The web build neither shows this legacy export nor accepts these old binary imports, and it never uploads or guesses them. Legacy `.xls` remains unsupported.

Rune always includes deterministic local planners for selection, file, and workspace actions. Immediately after language selection, onboarding lets a user add, fetch models for, edit, activate, or remove up to three OpenAI Responses, OpenRouter/OpenAI-compatible Chat Completions, Anthropic Messages, Gemini generateContent, or custom-protocol profiles, or choose local-only planning. Protocol is explicit profile state, never guessed from a model name; cross-provider failover is off by default and runs only after explicit user authorization, within visible per-task budgets. Personal credentials are AES-GCM encrypted into an HttpOnly `/api` cookie under `RUNE_CREDENTIAL_ENCRYPTION_KEY`; only redacted metadata reaches React. A deployment may still provide `OPENAI_API_KEY` and `OPENAI_MODEL`. Copy `.env.example` to `.env.local`, set a random credential-encryption key of at least 32 characters, and restart Rune before using personal profiles. Keys must never be committed. Instead of resending whole files, every adapter returns the same Rune-owned plan of at most eight typed operations per file: replace or insert a Markdown section by heading; upsert one typed CSV/flat-JSON row by unique key; add or update a typed column through exact keyed values; rename one exact non-colliding column; replace or insert a Deck slide by title; append one exact live Chart to Markdown/Deck; or use an exact `find → replace` fallback for precise inline and structural edits. A workspace plan contains at most four `patch_artifact` or `create_artifact` actions. Every creation has a short action-local handle; Query and Chart sources may reference either an exact visible artifact or a handle declared by an earlier creation. Handles are ordered capabilities, not filenames or ids: Rune resolves collisions, compiles them into real canonical references, and strips them from the review result. Forward, duplicate, wrong-kind, missing, or guessed-id references fail the complete plan. Rune still owns ids, filenames, extensions, language metadata, complete starter source, and every state write. Nothing is written unless the captured source revision is current, the complete next workspace validates, every affected Query-backed Chart passes local runtime preflight, and every changed existing file has a safety checkpoint.

For semantic HTML Presentations, the typed operation set also contains `replace_html_slide` and `insert_html_slide_after`. Each carries exactly one complete outer `<section>` and identifies the current compiler-proven page by zero-based index; Rune reindexes its own page metadata and number labels after structural changes. Existing Deck Markdown retains title-bound slide operations, and `append_chart` selects the correct readable syntax for either presentation format.

Selecting text in the source editor automatically exposes the **Selection** Agent scope. Rune binds the request to that artifact revision and its exact UTF-16 source offsets, limits the selected context to 16,000 characters, and proves after operation compilation that the complete prefix and suffix are byte-for-byte unchanged. The client repeats the same confinement check before Apply, then uses the normal concrete diff, checkpoint, adapter validation, dependency validation, and atomic persistence path. A stale, collapsed, oversized, or Unicode-splitting range is rejected without changing the workspace.

The live preview can create that same exact context without guessing from rendered DOM. Choosing a rendered Document heading, paragraph, list, quote, code block, table, or divider; an individual list item or GFM table cell; bold, italic, struck, inline-code, link, or image syntax; choosing its section outline; clicking a non-empty CSV/JSON cell; choosing a data row number; activating a provably direct SQL result field; choosing a Deck slide; or choosing a proven outer semantic HTML slide maps the visible object back to a deterministic range in canonical source, focuses that range in the editor, and activates Selection scope. A normal link click locates its complete Markdown source while Command/Control-click retains navigation. Document blocks and fragments use the same CommonMark/GFM syntax tree as rendering, while a compiler-owned offset map carries visible metric replacements back to their full canonical binding range. A Document fragment containing a Chart binding yields to the Chart's more precise cross-artifact datum provenance. A cell selects its complete source token, including CSV quotes or JSON string delimiters, while a row number selects the full record. A proven direct Data scalar can also be edited with Enter or its pencil control: CSV retains automatic scalar typing, flat JSON requires an explicit scalar type, and the exact lexical range is compiled back into source. Rune then validates the complete proposed workspace, runs every impacted Query/Chart consumer, checkpoints the old source, and persists once; stale, nested, invalid, oversized, or downstream-breaking edits leave the source unchanged. Markdown fences, quoted multiline CSV records, escaped quotes, nested JSON values, missing fields, Deck frontmatter, and slide separators are handled locally. Ambiguous duplicate JSON keys expose only their unambiguous full row; computed SQL cells, aggregates, multi-source results, nested JSON values, and unproven arbitrary HTML stay read-only until Rune can prove an exact mapping.

That mapping now runs in the other direction as well. Moving the canonical-source caret or selecting a range resolves against the current revision and chooses the smallest proven containing preview target—Document fragment before block before section, Data cell before row, or the exact Deck slide/Chart spec—then highlights and scrolls it into view. Nested list items and inline semantics win by their smaller exact range; a shared table-cell boundary prefers the cell beginning at the caret. A cross-block or cross-cell selection may fall back only to a section, block, or row that still fully contains it. Source-only headers/frontmatter, Query source, cross-section/row selections, and other unproven ranges produce no link instead of a fuzzy match. DOM attributes are only destinations for a parser-proven id, never source authority; a collapsed caret remains ordinary file editing and does not silently grant Selection Agent access.

Controlled preview editing also has a non-persistent synchronization layer. While a user edits one proven Document section/block, Data scalar cell, Deck slide, or complete Chart spec, Rune projects that draft into a full canonical-source candidate and mirrors it in the left editor with the exact replacement range highlighted. The canonical artifact, device draft, dependency graph, checkpoints, exports, folder sync, and Agent context remain unchanged until Save passes the existing compiler/runtime gate and one checkpointed persistence write. The source mirror is read-only during that short-lived visual edit so there is only one draft writer; Cancel or Escape destroys it and restores the unchanged canonical source immediately. Invalid drafts remain visibly marked and cannot be saved.

Agent review now uses the same live-feedback principle without weakening review-before-write. Once an Agent plan passes static and runtime preflight, Rune projects every patch and creation into one complete in-memory candidate workspace. The left pane can inspect any proposed source, including a not-yet-created artifact, while the right pane recompiles the selected artifact against the entire proposal. An unchanged downstream report or presentation can therefore show the effect of proposed Data, Query, or Chart changes before Apply even though its own source diff is empty. Both panes are read-only during this projection; canonical artifacts, checkpoints, device storage, folder sync, and exports remain on the original revision until Apply revalidates and persists the transaction atomically. Stale or invalid proposals expose no partial candidate.

A proven Markdown section has its own pencil control and a two-pane section editor: the bounded source draft stays on one side while its safe live rendering updates on the other. A compact native toolbar adds or removes bold, italic, strikethrough, collision-safe inline code, links, bulleted/numbered lists, and quotes without parsing rendered DOM; ⌘/Ctrl B, I, and K use the same compiler and restore the exact textarea selection. Save resolves the same target against the current artifact revision, permits prose and same-level title changes, preserves fenced pseudo-headings, and proves every byte outside the exact section unchanged. It rejects empty/no-op/oversized drafts, added or removed visible headings, heading-level changes, and any changed `{{ ... }}` live binding; structural and dependency work stays in canonical source or the reviewed Agent flow. The complete workspace validates before Rune checkpoints and persists once, then the left source selection and right section state advance together.

Each proven top-level Document block now separates **locate** from **edit** in the rendered paper. Hover, focus, touch, or F2 exposes a bounded editor for one heading, paragraph, list, quote, fenced code block, or GFM table; dividers remain navigation-only. The draft is reparsed with the same CommonMark/GFM grammar and must remain exactly one block of the same type, while headings must retain their level and every live binding must stay byte-stable. Save re-resolves the revision, replaces only the exact block range, then reuses the complete workspace-validation, checkpoint, runtime-impact, and atomic persistence transaction. Cancel, stale source, type changes, multi-block drafts, no-ops, or validation failures write nothing.

The same proven block identity now supports explicit **insert before/after**, **move one block up/down**, and **delete one block** structure operations. A new draft must parse as exactly one supported CommonMark/GFM block and cannot introduce live bindings; moving preserves both blocks byte-for-byte and swaps only adjacent AST siblings; deleting the last block is forbidden. Heading actions clearly warn that only the heading moves or disappears—not its following section—and deleting a bound block names the binding loss. Every operation opens a keyboard-contained review with the exact canonical-source diff, then recompiles against the current revision, validates the complete workspace, creates a checkpoint, and performs one atomic device write. Unsupported top-level HTML, stale targets, ambiguous boundaries, cancellation, and persistence failure remain zero-write outcomes.

A proven Deck Markdown slide exposes the same explicit select-versus-edit split. Its controlled editor owns only the slide's supported layout, optional plain-text eyebrow, and bounded Markdown body, while a separate no-script iframe compiles that draft as a one-slide Deck using the current theme and live workspace bindings. A proven semantic HTML slide instead exposes its exact outer `<section>` as controlled source: the left pane mirrors the complete proposed HTML, and an isolated iframe recompiles the full candidate without granting rendered DOM authority. Both save paths re-resolve the exact current target, preserve every byte outside it and every `{{ ... }}` binding, validate the complete workspace, checkpoint, and persist once. Deck frontmatter, slide insertion/deletion/reordering, dependency changes, and unproven HTML structure remain source/review operations.

A valid standalone Chart exposes two different source-bound actions above its live view. **Source** selects the complete current Chart JSON; **Configure** opens typed controls for title, description, bar/line/area mark, category/value fields, sort, number format, six-digit accent color, and one-to-twenty visible marks. The bound Data/Query identity is deliberately read-only in this panel. Every draft is recompiled against fields derived from that exact readable source and rendered with current runtime data. Save regenerates complete strict Chart JSON, then validates the workspace, runs the affected Query/Chart impact graph, checkpoints the prior source, and persists atomically. Invalid fields, nonnumeric values, stale Query evidence, no-op/invalid specs, or downstream breakage write nothing; changing source identity remains an explicit canonical-source or reviewed Agent operation.

Charts carry field-level provenance across artifact boundaries. A Chart can read canonical Data directly or consume the current result of a Query, using a categorical bar, ordered line, or ordered area mark. Direct-data marks retain their exact row and category/value cells; Query-backed marks preserve exact canonical cell targets only for direct projected fields, while calculated fields stay read-only. Duplicate labels never require fuzzy matching. Clicking or keyboard-activating a provable label plus its bar, line point, or area point switches to the underlying CSV/JSON artifact and enters the same confined Agent flow. Static Deck/HTML/Office/PDF snapshots remain non-interactive handoffs, and a mark stays read-only when its current source cannot produce an exact cell target.

The **Data graph** activity shows the current source-to-consumer topology rather than a manually maintained diagram. Rune recompiles legacy metric, `workspace_data`, Query-to-scalar-metric, Data-to-Chart, Query-to-Chart, and chart-embed edges from every current artifact revision, exposes unresolved intent, and makes both `Data → SQL → metric → Document/Deck` and `Data → SQL → Chart → Document/Deck` navigable. A Query with `-- rune:data "artifact-id"` contributes an edge from that exact Data artifact, so folder or manifest reordering cannot silently change its input. The same graph selects an upstream-closed Workspace Agent context: only components rooted at the selected artifact or an explicit pin are considered, at most seven files and 180,000 source characters are sent, and original workspace order preserves the remaining legacy first-Data semantics. A pin control beside each file lets the user deliberately bridge bindings the source cannot express—for example, coordinating two independent Markdown briefs—without persisting a hidden relationship; up to six pins last only for the current session and each pulls in its required upstream sources. The server independently recompiles supplied edges and rejects any disconnected file not explained by the selection or a pin before model work. The deterministic fallback receives that same pack, while the complete device workspace is still revision-checked and validated before Apply. Large or incomplete context falls back locally instead of dropping a pin or broadening model access.

When that verified Workspace context contains Query artifacts, a configured provider receives runtime evidence through a two-step handshake. The first request sends sources and graph identities only; after the server confirms that a provider exists, it asks the browser for the exact Query ids it needs. Rune then runs those Queries locally against their resolved Data revisions and retries once with at most 20 rows, 32 columns, 400 cells, 500 characters per string, and 20,000 JSON characters across the evidence pack. Runtime errors are returned as bounded feedback instead of being disguised as results. Evidence is advisory, can be truncated, is never persisted, and is available only in Workspace scope where those canonical Query and Data sources already passed the graph boundary. With no configured provider Rune returns the local fallback immediately and does not start DuckDB merely for model context.

Any Agent plan that changes Data, SQL, or Chart source—provider-backed or deterministic, in Selection, File, or Workspace scope—must pass a second local boundary before its diff can appear. Rune constructs the complete proposed workspace in memory, finds every Query bound to proposed Data, every directly changed Query, and every Query selected by a changed or newly created Chart, then executes that impact set against exact proposed revisions. It verifies affected legacy metrics, Query scalars, direct-Data Charts, and Query-backed Charts. A disconnected new Data source or direct-Data Chart never runs unrelated SQL. If a configured model's first concrete proposal fails, Rune may send that unapplied proposal plus a bounded compiler error back to the same model exactly once, using the unchanged canonical request and any already-verified Query evidence. The response must be a complete replacement operation plan and pass the server compiler plus the same full local impact graph again. Only that successful replacement becomes reviewable, clearly labelled as repaired once; failed feedback construction, transport, response validation, or second preflight stops with no local fallback and changes no source, checkpoint, folder, or device state. Deterministic local plans never enter this repair path. Canonical source, Rune's compilers, explicit review, and the captured revision remain the authority.

**New** starts any canonical artifact without first creating a file elsewhere. Document, Data, and Presentation use minimal Markdown, two-column CSV, and one-section semantic HTML templates. Query requires an explicit Data selection and writes a readable first-line `-- rune:data` identity plus `SELECT * FROM workspace_data`; Chart requires an exact Data/Query source, category/value fields, bar/line/area mark, and number format, then writes complete strict Chart JSON. Numeric Data fields are surfaced as defaults without hiding the exact source choice. A new Chart can optionally be embedded in a selected Markdown report, semantic HTML presentation, or existing Deck during the same confirmation: Rune creates the reusable Chart, appends one readable binding, checkpoints the changed consumer, validates the complete graph, and performs one device write. Workspace Agent can express the same dependency chain with ordered symbolic handles; the no-key quick command `根据收入数据创建分析、图表和报告` prepares a bound Query, live Chart, and linked report in one review transaction. Invented fields, foreign sources, guessed or forward identities, runtime-invalid values, or storage failure produce no partial file.

Every pending Agent mutation also gets a collapsible **Transaction map** compiled from the current and complete proposed canonical workspaces. It distinguishes new and edited files from unchanged inputs and transitively validated consumers, and marks dependency edges as added, removed, updated, or retained. The map never trusts provider handles or rationale and never replaces the concrete source diff: selecting a changed node opens its exact diff, while the existing runtime-preflight card records which local Data/Query/Chart impact was actually executed. A single-file proposal with no binding still remains a normal review instead of inventing a graph.

Opening a `.sql` artifact lazily downloads a version-pinned DuckDB-Wasm runtime. Its optional first non-empty line, `-- rune:data "artifact-id"`, binds `workspace_data` to one exact CSV/JSON artifact; imported older SQL without the directive keeps a visibly labelled first-Data fallback. Rune materializes that resolved parser output in exact source order, then runs the query entirely in the browser. For a conservative single-table, row-preserving `SELECT`, Rune carries an internal source-row identity through filters, sorting, aliases, and limits: direct projected columns and result row numbers can open the exact CSV/JSON token or record, while calculated fields remain visible but non-targetable. `WITH`, aggregate, `DISTINCT`, grouping, JOIN, set, pivot, sampling, window, or row-expanding query shapes still run but expose no edit capability. A Chart may name the Query artifact as its source; Rune infers a conservative output schema for workspace validation, waits for a snapshot bound to the exact Query and resolved Data revisions, and refuses missing, mismatched, stale, or truncated results. Documents and Decks may likewise bind a numeric scalar with `{{ metric("query-id", "output-column", "currency|number|percent") }}`. A scalar compiles only from the current non-truncated Query/Data snapshot, exactly one result row, an unambiguous output column, and a finite numeric value; static schema drift or runtime cardinality/type drift fails closed. The hosted app needs no database for this workflow.

Chart artifacts use a bounded `.chart.json` schema that names an existing Data or Query artifact, exact category/value columns, and a `bar`, `line`, or `area` mark. Bar compares categories; line and area preserve the explicit source/value sort as an ordered series and normalize negative, flat, or positive finite values without inventing data. Area adds a bounded baseline fill for magnitude or volume sequences while keeping the same exact point provenance. Query-derived fields must have explicit `AS` aliases so the output contract remains reviewable without executing SQL during every edit. The same `{{ chart("artifact-id") }}` reference compiles into a React chart inside Markdown and escaped static HTML inside the sandboxed slide runtime; schema drift blocks the whole pending workspace transaction.

Visible metric, chart, count, and export numbers use a Rune-owned formatter instead of runtime-dependent compact `Intl.NumberFormat` output. Grouping, compact suffixes, signs, rounding, and trailing-zero removal are therefore identical in the Cloudflare server render, browser hydration, live React preview, sandboxed Deck HTML, and frozen Office/PDF output. This avoids turning a harmless engine-level locale difference such as `$970K` versus `$970.00K` into a React hydration failure.

Presentation source defaults to bounded semantic `.html`: one metadata-bearing `<main>` owns the document and each complete outer `<section>` owns one source-linked page. Rune-created HTML keeps headings, paragraphs, lists, tables, page identity, and literal metric/Chart bindings readable; Preview renders each page in its own scriptless sandbox and supports direct exact-section editing with a complete live Source mirror. Existing `.deck.md` remains a supported typed-layout format with strict frontmatter, `---` separators, controlled metadata, and a small Markdown block grammar. Imported or hand-authored HTML receives the same section capabilities only when its source structure can be proven. Both formats can cross a reviewed temporary Deck projection for deterministic Office/ODF/PDF handoff, and semantic HTML may still create an optional independent Deck copy when that stricter model is useful.

**Import** accepts `.pdf`, modern `.docx/.xlsx/.pptx`, and `.odt/.ods/.odp` files without uploading them. One ordered lightweight adapter list owns the picker extensions, case-insensitive format match, 2 MB readable-source or 12 MB package limit, and lazy conversion entry; ordinary import and OCR continuation consume that same list. The PDF path lazily loads a local PDF.js worker, extracts selectable text with page provenance, infers bounded headings/lists/paragraphs, removes repeated edge headers or footers, and produces one reviewable Markdown Document. When pages contain no selectable text, Rune stops before reading their pixels and opens a separate bilingual OCR setup: the user chooses exact detected page ranges and English, Simplified Chinese, or both. PDF.js then renders only those pages in the browser and a bundled same-origin Tesseract worker recognizes them sequentially with stoppable progress; page images and text are never uploaded. Each OCR block carries its original page number, rounded average confidence, an explicit verify-against-original notice, and a separate fidelity warning in the final atomic import review. It never executes document JavaScript or asks for a password in the browser, and columns, tables, images, fonts, links, annotations, bookmarks, exact layout, and OCR certainty are explicitly treated as lossy rather than silently guessed. Separate lazy compatibility converters map DOCX or ODT structure to Markdown, each visible XLSX or ODS worksheet to a separate CSV artifact, and ordered PPTX or ODP text/tables/pictures to compiler-proven semantic HTML. Rune validates the complete source-and-asset batch and resolves collisions, then opens a keyboard-accessible review with every generated filename, a bounded source preview, and all omission warnings. Only explicit confirmation performs the single compensating device transaction; cancel, stale workspace context, validation failure, asset/storage failure, or stopped OCR leaves the current workspace unchanged.

**Office export** performs the reverse compatibility handoff without changing canonical source. Markdown becomes semantic DOCX, CSV/JSON becomes a values-only XLSX worksheet, and Deck Markdown becomes a 16:9 PPTX with ordered text, bullets, tables, a slide master, layout, Rune theme, and verified local images as package media. Workspace metrics are compiled before packaging; every referenced Query is rerun against its exact Data revision so scalar values and Query-backed charts freeze the same current evidence into the package. A referenced bar Chart becomes a selectable semantic bar table in DOCX; line and area Charts become semantic trend tables; PPTX receives editable native text and vector bar/line/area geometry. Runtime features that still cannot be represented are called out rather than guessed. Every package is deterministic, generated locally with standard OOXML parts, and held behind the same keyboard-accessible fidelity review before one browser download. The original `.md`, `.csv/.json`, and `.deck.md` download remains available beside it.

Rune-owned semantic HTML Presentations reach PPTX through a temporary, immutable strict Deck projection in the same export review. Title, language, theme, source lineage, compiler metric grids, and literal live bindings survive that projection; CSS and arbitrary imported markup remain explicit fidelity limits. Canonical `.html` is never replaced.

**OpenDocument export** provides the parallel standards-based handoff as ODT, ODS, or ODP. Markdown structure becomes semantic ODT; verified Rune local Document and Deck images become packaged pictures with manifest media entries; canonical CSV/JSON becomes a typed values-only ODS sheet; and validated Deck Markdown or compiler-proven semantic HTML becomes ordered ODP pages with text, bullets, tables, and current Chart data as selectable tables. Packages use ODF 1.3 content, style, MIME, and manifest parts, an uncompressed first `mimetype` entry, fixed ZIP timestamps, no formulas or executable scripts, and a 12 MB output cap. The same revision-bound Query snapshot, fidelity review, and explicit one-download confirmation apply. Exact pagination, formulas, comments, tracked changes, animation, and advanced master styling are not claimed.

**Standalone HTML export** turns a Deck Markdown artifact into one portable, scriptless `.html` file. It resolves legacy metrics, reruns every Query referenced by a scalar metric or Chart, verifies each referenced local image, and freezes those values, views, and image bytes before export; the result embeds all styling and images, contains no external resources, and adds print rules that place each 16:9 slide on its own page for browser PDF handoff. The deterministic file is capped at 12 MB and uses the same stale-context check and explicit review-before-download transaction as Office export.

**Direct PDF export** creates the final handoff without a print dialog or hosted renderer. Markdown Documents become paginated A4 files with semantic headings, paragraphs, lists, quotes, code, tables, local images, page numbers, and vector Chart snapshots; Data becomes a repeating-header landscape A4 table with bounded columns, rows, wrapping, and visible truncation notes; Deck Markdown and compiler-proven semantic HTML become one fixed 16:9 PDF page per slide. Rune reruns every referenced Query against its exact Data revision, embeds a bundled Unicode font, fixes metadata for byte-deterministic output, and exposes every fidelity limit before confirmation. The PDF contains no JavaScript, forms, external resources, live bindings, or editable source structure; it is capped at 12 MB and leaves the canonical workspace unchanged.

The consolidated **Export** menu keeps the canonical source download beside reviewed handoff formats. Data can be normalized locally into deterministic UTF-8 formula-safe CSV or rectangular JSON, or exported as values-only XLSX, ODS, and fixed table PDF. Conversion never mutates source or checkpoints, and every generated artifact waits in the same fidelity-review transaction before the browser downloads it.

On browsers that implement the File System Access API, **Open folder** connects Rune to real source files plus a readable `rune.workspace.json` manifest. A workspace with local images uses manifest version 2 and stores exact content-hash bytes in `.rune-assets/<sha256>.<ext>` while Markdown keeps the same `rune-asset:` reference. Pull validates the complete folder, every asset size/format/hash, and exact reference-to-manifest closure before importing assets and checkpointing/replacing device source; any device persistence failure compensates newly imported bytes. Push verifies every referenced device asset before writing it, writes assets before source and the manifest last, and blocks missing/corrupt resources rather than creating a broken folder. Existing version 1 source-only workspaces remain compatible. The handle is intentionally session-scoped; regular import and per-file download remain available as fallbacks.
