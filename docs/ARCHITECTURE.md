# Rune Architecture

Rune is an AI-native artifact workspace. Human-readable source is canonical; editors, previews, exports, and agents are replaceable clients of that source.

## Product boundary

The first release is a local-first vertical slice, not a pixel-fidelity Office compatibility suite. It must make documents, data, and presentations feel like one product while keeping their compilers independent.

```text
Workbench UI
  ├─ Workspace state and persistence
  ├─ Static task assembly
  │    ├─ capability → reviewed source session → pure task provider → transaction
  │    └─ optional bounded model outline/questions → Rune-owned task compiler
  ├─ Agent command surface
  ├─ OOXML import port
  │    └─ DOCX → Markdown · XLSX → CSV · PPTX → temporary Deck proof → semantic HTML
  ├─ Export ports
  │    ├─ canonical source → DOCX · XLSX · PPTX
  │    ├─ proven semantic HTML → controlled Deck projection → PPTX · ODP · fixed PDF
  │    ├─ semantic HTML or Deck Markdown → portable scriptless HTML
  │    └─ Markdown / Deck Markdown → fixed local PDF
  ├─ Dependency compiler
  │    └─ shared data → legacy or Query metrics / chart models → document / slides
  └─ Artifact registry
       ├─ Markdown adapter → document preview
       ├─ Data adapter     → parsed grid
       ├─ Query adapter    → DuckDB-Wasm result grid
       ├─ Chart adapter    → validated JSON + local semantic bar/line/area view
       └─ Slides adapter   → semantic HTML by default or compatible Deck Markdown → continuous compiler-owned slide sandboxes
```

## Stable contracts

### Interface composition boundary

Rune's page remains a product workbench, not a generic plugin host. The shell owns geometry, persistence coordination, and business dispatch; feature code may contribute discoverable interface metadata through the React-free `surface-registry` without gaining those capabilities.

```text
surface owner declares kind (single | ordered list)
  └─ feature registers { surface, stable id, order, value }
       ├─ collision / unknown surface / invalid cardinality → fail loud
       ├─ consumer reads a deterministic immutable snapshot
       └─ disposer removes exactly that contribution
```

Workspace view definitions and Quick Actions are the first consumers. React components receive snapshots and callbacks; the registry cannot render, fetch, persist, access credentials, or mutate Artifacts. This keeps a migration path toward independently owned feature surfaces without paying for Cordis profiles, runtime package loading, or a third-party plugin security model before those are real requirements.

The workspace frame separately owns panel interaction. Source and Preview remain mounted while focus views change only grid tracks and accessibility state. The separator captures one pointer on its element, coalesces movement to one update per animation frame, disables track easing during the gesture, and commits the preference once after settle. Keyboard arrows, Shift increments, Home reset, RTL logical direction, reduced motion, and the responsive single-pane boundary are part of the same contract.

Source-to-Preview positioning is a separate mounted-surface effect in `use-source-preview-scroll.ts`. Domain parsers and compilers still derive immutable UTF-16 target identity; the hook only selects among already-rendered provenance attributes through the React-free `selectPreviewNavigationCandidate` helper and never inspects rendered text or iframe DOM. Entering a different artifact/target centers the visible node. A later caret movement within the same target uses nearest-edge scrolling, which restores a Preview manually displaced by the user without repeatedly centering ordinary in-block navigation. Preview-to-Source continues through the revision-bound `prepareSourceNavigation` plan and the Workbench's focus/selection/textarea-scroll executor. The hook has no artifact mutation, storage, network, provider, credential, or persistence capability. Real reviewed-import browser gates cover long Markdown sections, exact CSV cells, and semantic HTML pages in both directions. See [ADR 0046](decisions/0046-source-preview-positioning-recovers-the-active-target.md).

Controlled Preview editing uses a second narrow mounted-surface boundary, `use-visual-source-draft.ts`. Each typed visual compiler owns the exact target and returns a complete candidate source plus the replaced range and validation errors. `useVisualSourceDraftMirror` can only publish that value to the Workbench or clear it; the Workbench renders it read-only in Source and retains the sole persistence/checkpoint authority. `null` means no visual draft, while `undefined` is a deliberate ownership handoff used when the Deck surface keeps its semantic-HTML child editor mounted. This prevents the parent from clearing the child's live candidate during the same render lifetime. Browser gates prove live candidate rendering, exact cancellation, and canonical save for Markdown sections, CSV cells, Chart specs, and semantic HTML slides. See [ADR 0047](decisions/0047-visual-editors-share-one-complete-source-draft-bridge.md).

An artifact adapter owns its starter source, source language, filename detection, validation, display metadata, compact statistics, and local suggestion metadata. The closed first-party vocabulary is composed through one React-free exhaustive registry: missing, duplicate, unknown, or malformed adapters fail during module composition, and consumers receive an immutable ordered snapshot. Creation, import detection, validation, the status bar, and Quick Actions all read this authority instead of maintaining parallel kind switches.

Preview is the adapter's React consumer, not a value stored in the domain registry. It uses an exhaustive `Record<ArtifactKind, renderer>`, so TypeScript requires a renderer whenever the kind union grows without allowing React, browser state, persistence, or write capabilities into `app/lib`. The workbench continues to own selection, persistence, history, imports/exports, reviews, and agent actions. This boundary lets us extend SQL, charts, Deck Markdown, Office import, or a desktop filesystem without rewriting unrelated shell consumers.

Rune-authored presentations now start from `semantic-html-presentation.ts`. One readable `<main data-rune-format="presentation-v1">` owns bounded title, theme, language, origin revision, audience, and purpose metadata; each outer `<section data-slide-index>` is one page with stable page-number chrome, and live metric/Chart bindings remain visible source tokens. New, sample, focused-task, and Agent creation all use this factory. Exact helpers replace or insert one complete outer section and then reindex only Rune-owned slide metadata and `NN / TT` labels. Refresh preserves the existing target format instead of silently converting an older Deck. This is the default authoring contract, not a license to interpret arbitrary DOM. See [ADR 0044](decisions/0044-semantic-html-is-the-default-presentation-source.md).

Deck compilation remains the typed compatibility branch. `compileDeckSource` returns the complete scriptless HTML document used by export plus ordered standalone one-slide documents derived from the same parsed model and block compiler. The workbench lays those documents out as one continuous vertical flow, preserves each 16:9 page boundary, and asks the browser to lazy-load each independent sandbox. Every canvas binds its exact `PreviewSourceTarget` to an accessible outer hit target; React never reaches into the iframe or recreates slide HTML. Canonical source selection scrolls the shared Preview surface to the corresponding page, and activating any page delegates back to the same revision-checked Source navigation capability.

Semantic HTML crosses that same presentation boundary only after `compileLegacyHtmlSlides` proves source identity. The React-free scanner accepts one explicit `<main>`, derives complete outer `<section>` ranges while ignoring comments and raw-text bodies, and fails closed on scripts, malformed structure, more than 120,000 source characters, or more than 40 pages. It returns frozen exact UTF-16 slices and independent scriptless documents that retain only the original `<html>` / `<main>` opening tags plus shared inline styles. Preview consumes these pages through the existing continuous flow and navigation contract; it never queries iframe DOM or matches rendered text back to source. Rune-owned files additionally carry the `presentation-v1` metadata required for safe structural reindexing; imported HTML without that marker can still be proven page-by-page but never gains Rune-owned metadata rewriting by inference. Unproven HTML receives no target. References below to unlinked or false-target-free “legacy views” mean only unproven compatibility input; proven semantic sections enter the same continuous-page, reverse-navigation, and controlled source-edit gates as Deck Markdown.

Semantic HTML local pictures reuse the existing media authority rather than creating an HTML asset subsystem. Canonical markup stores one ordinary `<img src="rune-asset:sha256:<digest>" alt="…">` inside a page; IndexedDB or the connected-folder `.rune-assets` closure remains the only byte owner. Preview resolves that exact reference to a temporary approved `blob:` URL while keeping source ranges unchanged. Manual insertion targets one compiler-proven section, inserts before its closing tag, enforces one primary picture, and reuses the existing source review, checkpoint, asset-first persistence, and compensation path. Standalone HTML resolves reviewed assets to `data:` only in the exported bytes, applies a restrictive CSP, and rejects active elements, event attributes, CSS resource loads, links, and unapproved resource attributes. See [ADR 0045](decisions/0045-presentation-package-imports-land-on-semantic-html.md).

Compatibility export uses a second one-way boundary over that proven structure. `convertSemanticHtmlPresentationToDeck` maps readable headings, paragraphs, lists, bounded rectangular tables, supported layout hints, and interface language into an immutable temporary Deck artifact. Office, OpenDocument, legacy-desktop, and PDF writers continue to consume only the existing strict Deck model; no writer gains an arbitrary DOM interpreter. The projection exists only inside the reviewed export attempt and never replaces canonical HTML. CSS, positioning, animation, forms, links, unverified media, irregular tables, and unsupported elements are explicit deterministic warnings or bounded fallbacks. The converter cannot fetch, persist, download, access credentials, call a provider, or mutate source. See [ADR 0037](decisions/0037-semantic-html-handoff-reuses-the-controlled-deck-model.md).

The same projection can prepare an independent editable workspace copy, but only through `semantic-html-editable-copy.ts`. Preview contributes a capability callback only for a currently valid semantic HTML artifact; the workbench dynamically loads the React-free helper, requires the exact object and source revision from the current workspace, and sends the converted Deck through the existing import-review transaction with purpose `editable-copy`. Conflict resolution owns the new id and `.deck.md` filename. Confirmation performs the existing one additive device write and selects the new artifact; cancellation, stale workspace state, invalid conversion, or persistence failure leaves every source unchanged. The original HTML is never replaced or silently linked to the copy, and the fidelity panel explicitly says later edits do not synchronize. The helper cannot access storage, downloads, network, providers, credentials, images, or mutation APIs. See [ADR 0039](decisions/0039-semantic-html-enters-visual-editing-through-a-reviewed-copy.md).

Proven semantic HTML sections also have a narrower direct-edit capability that preserves HTML as canonical source. `visual-semantic-html-slide-edit.ts` accepts only a current exact outer-section target from the same compiler, normalizes the controlled textarea draft to the source newline convention, and reconstructs the complete candidate by replacing that range alone. It requires exactly one outer `<section>`, at most 16,000 characters, no script, the same slide count and live-binding token sequence, and byte-identical content outside the target. A complete recompile produces the isolated draft `srcdoc`; the editor never reads or mutates iframe DOM. While the draft is valid, the left Source pane receives the complete proposed HTML through the existing read-only visual-source mirror. Save uses the same `commitVisualSourceEdit` path as Document, Data, Chart, and Deck: exact-revision re-resolution, whole-workspace validation, runtime preflight, checkpoint, one persistence write, selection, and focus. The compiler and editor have no storage, network, provider, credential, download, or second mutation authority. See [ADR 0041](decisions/0041-semantic-html-sections-edit-canonical-source-directly.md).

The provider-facing contract is a bounded, source-native operation plan:

```ts
  end: number; // exclusive UTF-16 offset
};

type PreviewSourceTarget = SourceSelection & {
  kind:

    | "document-block"
    | "document-fragment"

    | "data-cell"

  label: string;

  kind: "document-fragment";
  fragmentType:
    | "list-item"
    | "table-header-cell"
    | "table-cell"

    | "italic"
    | "strikethrough"
    | "inline-code"
    | "link"
    | "image";
  rowIndex?: number;
  columnIndex?: number;
};

  kind: "data-cell";
  rowIndex: number;
  columnIndex: number;

  value: number;
  formatted: string;

};

  artifactId: string; // canonical Data artifact, never the derived Query view

  sourceColumn: string;
};

  queryArtifactId: string;
  querySource: string;
  dataArtifactId: string;
  dataSource: string;

};

  queryArtifactId: string;
  dataArtifactId: string;

  | {
      status: "ready";
      columns: string[]; // ≤32
      rows: DataCell[][]; // ≤20 rows, ≤400 cells
      visibleResultRowCount: number;
      totalColumnCount: number;
      resultTruncated: boolean;
      evidenceTruncated: boolean;
    }
  | { status: "error"; error: string }

type AgentRuntimeRepair = {
  attempt: 1; // the only automatic repair request allowed for one user action
  failure: string; // normalized local compiler/runtime failure, ≤1,000 characters
  proposedArtifacts: Array<{
    artifactId: string;
    name: string;
    kind: WorkspaceArtifact["kind"];
    language: string;
    proposedSource: string; // compiled first proposal, still unapplied
    isCreation: boolean;
  }>; // 1–4 exact proposal sources; ≤100,000 each and ≤180,000 in Workspace scope
};

type RuntimeImpactPreflight = {
  dataCount: number;
  queryCount: number;
  legacyMetricConsumerCount: number;
  scalarConsumerCount: number;
  chartConsumerCount: number;
  dataNames: string[];
  queryNames: string[];
};

type QueryMetricReference = {

  column: string;
  format: "currency" | "number" | "percent";
  rowIndex?: number; // explicit multi-row selection; absence still requires exactly one row
};

type WorkspaceDependencyEdge = {
  fromArtifactId: string; // canonical source
  toArtifactId: string; // consumer
  kind: "metric" | "query" | "query-metric" | "chart-data" | "chart-query" | "chart-embed" | "deck-origin";
  references: string[];
};

type AgentArtifactReference =
  | { kind: "artifact"; artifactId: string } // exact visible canonical id
  | { kind: "creation"; handle: string }; // exact earlier action-local handle

    artifactId: string;
    status: "created" | "edited" | "validated" | "input";

```

Rune applies each operation sequentially to the exact source sent with the request. Markdown sections resolve one exact heading and include its nested subsections until the next heading at the same or a higher level. Data rows resolve one exact typed key in an existing column, accept only flat JSON cells, and preserve CSV versus JSON plus JSON array versus single-object shape. A Data-column upsert requires an existing globally unique, non-empty typed key column, never changes that key or inserts a row, and accepts at most 200 keyed scalar values. Adding a column requires one value for every existing row (or an empty value list for a header-only empty CSV); updating an existing column may target a subset but rejects repeated, missing, or unchanged keys. A column rename resolves one exact current header, requires a trimmed single-line non-colliding replacement, preserves column/property order, and is still only a proposal—the complete downstream SQL/Chart runtime gate may veto it. Deck slides resolve one exact `#`/`##` title; inserted or replacement fragments must be complete slides without a `---` separator. Semantic HTML presentations instead expose `replace_html_slide` and `insert_html_slide_after`, each bound to one compiler-proven zero-based outer-section index and one complete replacement/insertion section; Rune-owned metadata is reindexed after structural changes. `append_chart` resolves one exact existing Chart or an earlier Chart creation handle, refuses duplicate bindings, and appends a Markdown section, a semantic HTML section, or a strict Deck split slide according to the exact target format. It is not exposed in File/Selection provider schemas. The `replace_text` fallback still requires one exact, non-empty, unique literal in the evolving revision.

A create action passes its discriminated typed intent through Rune's shared identity/template factory. Every creation declares a unique lowercase action-local handle. Core files need kind/title; Presentation creation receives Rune's semantic HTML starter by default, while Query and Chart use a discriminated source reference that names either an exact original visible artifact or an earlier successful creation handle and Chart also supplies exact fields, mark, and format. The compiler walks actions in order, resolves id and filename collisions together, compiles edits, records the handle only after that creation succeeds, and writes only the resulting canonical id into Query/Chart/Document/Presentation source. Handles never appear in compiled review output, persistence, folder manifests, exports, or dependency graphs. Typed edits run against the exact starter source; zero edits are valid when the template already expresses the request. The final graph independently rejects any created-to-touched dependency that was not authorized by an explicit handle, so a lucky guessed slug cannot masquerade as a symbolic reference.

In Selection scope, Rune compiles the narrower operation schema against the full captured source and additionally proves that the exact prefix before `start` and suffix after `end` are unchanged; a CSV header rename can therefore fit an exact header selection, while a whole-column value update or normalized JSON rewrite normally requires a wider range. The provider cannot send a final id, filename, extension, language, source text, or `nextSource`, cannot patch a just-created file, and cannot use a forward, duplicate, missing, wrong-kind, or guessed creation identity. Missing or repeated targets, invented sources/fields, artifact/operation mismatch, malformed fragments, duplicate keys, incomplete new columns, no-ops, cancelling sequences, foreign/duplicate artifact ids, incompatible template edits, selection-range crossing, or output above 120,000 characters reject the complete model plan. Only then does the server produce concrete patches/creations and run the whole-workspace safety gate before responding.

The UI previews every affected file, its operation count, line-change counts, and a bounded concrete source diff before accept/reject. New files are explicitly marked and diffed from empty source. It independently rebuilds dependency graphs from the current and complete proposed canonical workspaces, takes only the transitive upstream inputs and downstream consumers rooted at changed files, and renders a collapsible transaction map. Nodes distinguish created/edited sources from unchanged inputs and validated downstream consumers; union edges distinguish added, removed, field-contract-updated, and retained relationships, so deleting a binding cannot disappear from review merely because it is absent from the proposed graph. Shared consumers of an unchanged upstream input are not pulled in. The map consumes no provider handles or rationale and grants no new write capability; changed nodes only select the already-bounded concrete diff. Applying repeats the transaction boundary client-side: the captured workspace source revision must still match, patch ids must still exist and be unique, creation ids/names must still be new, every existing source must actually change, each adapter must validate, and the complete next workspace must compile without unresolved metric or chart bindings. Rune creates a pre-change checkpoint for every patched target, appends new artifacts, and performs one local persistence write before swapping UI state and selecting the first created file. Any failure keeps the whole current workspace unchanged. Model providers never write workspace state directly.

## Model provider boundaries

`POST /api/agent` is the general model-facing operation surface. Selection scope sends one artifact plus a non-empty, revision-bound UTF-16 range of at most 16,000 characters; File scope sends one complete artifact. Both require a schema-conformant `summary`, `detail`, and 1–8 discriminated operations. Workspace scope sends an upstream-closed pack of 2–7 canonical artifacts rooted at the selected file plus zero to six explicit context pins, within a 180,000-character envelope, along with the exact source-to-consumer edges and pin ids inside that pack. It requires a top-level rationale plus 1–4 discriminated `patch_artifact`/`create_artifact` actions. Patch ids must belong to that request and cannot repeat. Creation supports all five canonical kinds and requires one unique action-local handle. Query/Chart source references choose exact visible artifacts or earlier creation handles; Chart also names category/value fields, mark, and format. Rune deterministically supplies collision-safe identity, extension, language metadata, initial source, and handle resolution. Creation uses 0–8 edits against that documented template; patch actions retain 1–8. Provider instructions prefer section operations for documents; keyed row/column upserts or exact column renames for CSV/flat JSON; zero-based complete-section operations for semantic HTML presentations; title-bound slide operations for compatible Deck Markdown; and Workspace-only `append_chart` for a reusable existing or earlier-created Chart. SQL, Chart JSON, presentation metadata/frontmatter, and precise inline edits use exact `replace_text`. String fields are bounded from 40 to 16,000 characters by role, rows/columns carry explicit JSON-compatible scalar types, a column carries at most 200 keyed values, and provider output is capped at 8,000 tokens. Line numbers, regular expressions, arbitrary JSON paths, provider-authored source/metadata, generated-id guesses, forward handles, and direct state writes are intentionally excluded. The workbench receives only the compiled concrete mutation and never applies it automatically.

Focused tasks may expose a narrower model surface when the general operation vocabulary would grant unnecessary authority. `POST /api/tasks/document-briefing` accepts one exact Document of at most 100,000 characters plus title, audience, purpose, 4/6/8-slide count, and locale. Rune derives exactly two, four, or six bounded evidence excerpts and assigns request-local `source-N` capability ids. The model returns only a plain-text title and one to four plain-text bullets for each id, using every id exactly once. Server, client, and pure compiler repeat dynamic coverage and text-safety validation. The model cannot return a target id, filename, Presentation source, metadata, patch, creation, or write; Rune deterministically compiles a new target as semantic HTML and preserves an existing target's exact semantic-HTML-or-Deck format during refresh. Unconfigured, unavailable, invalid, oversized, and local-only paths retain the same deterministic task compiler.

Focused task clients share [`task-model-planning.ts`](../app/lib/task-model-planning.ts), a static discriminated port rather than fetch logic embedded in React. The workbench injects a same-origin `fetcher` capability and an optional progress callback. The port resolves only the task's exact current source, enforces its declared source limit before network use, reads at most 128 KB of response bytes, normalizes untrusted model metadata and token counts, recomputes task evidence locally, and runs the task-specific validator before returning a narrative or outline. It cannot access credentials, React, browser persistence, workspace mutation, checkpoints, or Apply. Missing sources, local mode, oversized sources, transport errors, non-OK responses, invalid JSON, oversized response bodies, and evidence-invalid output return an explicit deterministic-fallback outcome. See [ADR 0011](decisions/0011-inject-one-bounded-task-model-port.md).

`POST /api/tasks/operating-review` applies the same seam to one exact Data artifact of at most 100,000 source characters. Rune first validates the complete deterministic task locally, then derives at most twenty category aggregates in the same bar-sort or line-source order as its generated Query. The configured provider receives only task intent, selected field identities, and this bounded aggregate table. It may return at most two qualitative questions tied to unique request-local `result-N` ids and optional different comparison ids; copied category labels, static numbers, date/currency/percent text, markup, bindings, unsupported ids, or repeated primary evidence fail. Server, client, and pure compiler repeat validation. Rune converts accepted ids into live row-specific Query metrics and retains deterministic fallback, complete source ownership, runtime preflight, candidate review, and Apply.

The task may additionally carry one exact typed Data scope `{ field, value }` and one optional `comparisonScope`. [`operating-review-scope.ts`](../app/lib/operating-review-scope.ts) is the pure capability owner: it derives at most one hundred source-ordered distinct options, preserves string/number/boolean identity, derives numeric fields from only eligible rows, compiles escaped equality conditions, and rejects stale values. A comparison requires a primary scope, the same exact visible field, and a different typed value. Field eligibility covers the union of both selected row sets but ignores rows outside both. Filtering happens before field eligibility and local aggregation, so the form, pure compiler, server model input, generated SQL, Chart metadata, report, presentation, and saved rerun all resolve the same rows. The paired Query uses conditional aggregates, retains only categories proven on both sides through `HAVING`, and exposes primary, comparison, and `primary − comparison` fields; the change field is the Chart and live-metric contract. The Query casts compiler-validated eligible measures to `DOUBLE`; this prevents malformed text in excluded periods from making DuckDB bind the entire imported column as `VARCHAR`, without weakening validation inside either selected scope. Excluded periods cannot invalidate a selected pair; choosing all rows remains strict. A period label remains presentation metadata and never substitutes for source constraints. See [ADR 0009](decisions/0009-period-labels-do-not-prove-data-scope.md) and [ADR 0012](decisions/0012-comparisons-are-paired-exact-scopes.md).

Before a provider request, the task dialog projects this same pure evidence preparation result into a read-only preview. It exposes primary eligible rows, optional comparison rows, the derived excluded-row count, and at most the first five ordered aggregate groups; `groupCount` retains the total number of groups even though provider evidence remains independently capped at twenty. A paired preview shows both aggregates and their compiler-owned change. Values pass through the same exported Chart formatting function used by live rendering. React neither parses another aggregate nor broadens the input: incomplete, stale, malformed, unpaired, or empty mappings produce no preview and no provider call. See [ADR 0010](decisions/0010-preview-compiler-evidence-before-model-use.md) and [ADR 0012](decisions/0012-comparisons-are-paired-exact-scopes.md).

The provider port has four explicit transports: OpenAI Responses (`text.format` JSON Schema), OpenAI-compatible Chat Completions (`response_format.json_schema`), Anthropic Messages (one forced `submit_rune_plan` tool with the same input schema), and Gemini generateContent (`responseJsonSchema`). Each normalizes provider output and real usage fields into one `AgentOperationPatch` or `AgentWorkspaceOperationPlan`; the existing Zod parser, operation compiler, source/dependency/runtime gates, and Review remain the authority. Profiles never infer protocol from a model name. Every connection declares its structured-output capability and per-task token budget; Rune estimates bounded input before contact, passes the output ceiling through the native protocol, and checks provider-reported usage. Cross-provider failover is off by default and requires an explicit vault preference when at least two connections exist. Authorized requests follow the visible connection order, temporarily avoid a recently failed connection, and never continue after abort; routing still cannot expand context or write authority. Deterministic selection/file/workspace planners remain available when no active connection exists. The local workspace planner can create all five artifact kinds through the same factory and review transaction. Query/Chart source candidates come only from its explicit context pack, while collision-safe identity and final validation still use the complete workspace. A narrow workflow intent that explicitly asks for Data analysis, a Chart, and a report and/or presentation now prepares one concrete Query → Chart → deliverable creation batch. The local planner owns those identities directly rather than pretending to be a provider, but its result passes the identical mutation and runtime-impact gates. The hosted no-key path therefore demonstrates the complete creation loop rather than silently bypassing it.

Model setup preserves that server boundary through two credential sources. Deployment owners may still set `OPENAI_API_KEY` and `OPENAI_MODEL`. A user may instead create up to three personal OpenAI, OpenRouter, Anthropic, Gemini, or custom-protocol profiles through `/api/model-profiles`; one profile is active and takes precedence over deployment configuration. The key exists in the React password draft only until Save, crosses same-origin HTTPS, and is encrypted/authenticated with AES-GCM under a separate `RUNE_CREDENTIAL_ENCRYPTION_KEY`. The resulting 30-day cookie is `HttpOnly`, `SameSite=Strict`, and scoped to `/api`; client code receives only profile id/name/provider/protocol/base URL/model/timestamps plus a credential-present boolean. The cookie is treated as empty after tampering, schema failure, or master-key rotation, and production disables personal profiles when the master key is absent. The only localStorage model value remains the non-secret `auto | local` preference. API keys remain forbidden from workspace source, browser-readable persistence, checkpoints, folder manifests, analytics, logs, Git, URLs, and prompts. Rune Desktop protects the vault master key with Electron `safeStorage` and the macOS Keychain while keeping the decrypted key out of the renderer.

Custom provider URLs must be HTTPS public-DNS origins on port 443, without userinfo, query, fragment, IP literals, localhost/private suffixes, or a final generation path. This is a conservative SSRF and misconfiguration boundary, not a claim that arbitrary gateways are safe. `models` validation performs only a bounded authenticated `GET {baseURL}/models` using the selected protocol's header: eight-second abort, declared and streamed one-megabyte ceilings, at most eighty unique 120-character ids, no redirect, and no Artifact content. Agent calls have a 60-second abort and two-megabyte response ceiling. Responses and compatible Chat set `store: false`; Anthropic uses its pinned version header; Gemini receives a schema normalized to its documented subset. Provider errors do not echo response bodies that may contain sensitive evidence. Profile selection changes only transport and grants no new source or persistence capability; protocol/provider changes require a fresh key, and cross-provider fallback is forbidden without a future explicit user authorization contract.

## Agent Query evidence and runtime impact preflight

Workspace source tells a model how a Query is written but not what its current revision returns. Rune closes that gap without making result snapshots canonical through a configured-provider handshake. The first graph-validated request contains no `queryEvidence`. If no provider key exists, the API returns `MODEL_UNCONFIGURED` immediately and the browser uses the deterministic planner without loading DuckDB for model context. If a provider is configured and the exact Workspace pack contains Query artifacts, the API returns `QUERY_EVIDENCE_REQUIRED` with their ordered ids before any provider call. The client executes those Queries locally against their resolved Data revisions and retries exactly once. This means provider availability—not a speculative client guess—authorizes the extra local compute and evidence disclosure.

Each Query contributes exactly one identity-bound record in workspace order. A successful record contains at most 20 rows, 32 columns, 400 cells, 500 characters per string, and explicit original row/column counts plus runtime/evidence truncation flags; an execution failure contributes at most 500 characters of error feedback. The complete pack is capped at 20,000 JSON characters. The server checks schema, ordering, uniqueness, Query id, and resolved Data id against the same supplied sources before a provider call. Evidence exists only in Workspace scope, where those Query and Data sources are already inside the graph capability boundary. It is computed by the requesting browser, advisory rather than attested, may be incomplete, and is not persisted in source, local storage, checkpoints, folder manifests, logs, or Git. Model instructions require live metric/Chart bindings instead of pasted samples and forbid treating error or truncated evidence as complete.

A second boundary applies after either a provider or deterministic planner returns. If the concrete plan changes or creates any Data, Query, or Chart source, the workbench first builds the complete proposed workspace in memory with the ordinary mutation safety gate. It treats directly changed Queries, every Query whose resolved proposed Data id changed, and every Query selected by a changed/new Chart as the runtime impact set, executes each against that exact proposed Data revision, and rejects stale snapshots. It then recompiles affected legacy metrics and Query scalars and resolves every direct-Data or Query-backed Chart in the impact set. A disconnected new Data source or direct-Data Chart is still parsed and whole-workspace validated but does not cause unrelated Queries to run.

If a provider-backed first proposal fails this gate, Rune constructs one `AgentRuntimeRepair` from the unapplied compiled sources and the normalized failure. Existing files must retain exact id/name/kind/language identity, created files must retain Rune-owned non-colliding identity and canonical kind, every id/name is unique, at least one Data, Query, or Chart source is present, Selection proposals still preserve the exact outside prefix/suffix, and the proposal pack stays within the same per-file and total source envelopes. The original canonical artifact/workspace graph, prompt, selection, metrics, and already-verified Query evidence remain unchanged. The feedback is labelled untrusted advisory data: it cannot become a target, an instruction, a write capability, or evidence that the first plan was applied.

The provider must return a complete replacement typed-operation plan compiled against the original canonical revision; it cannot patch the failed proposal incrementally. The API echoes `repairAttempt: 1`, the client accepts only that marker, and the replacement passes the ordinary server operation compiler/safety gate followed by the complete browser-local runtime impact graph again. Only then can it become `pendingChange`, whose review card preserves the first bounded failure and says the plan was repaired once. Feedback construction failure, transport failure, an invalid/missing marker, invalid replacement operations, or a second runtime failure stops the action with no pending review, local fallback, source write, checkpoint, local-storage write, folder write, or React workspace mutation. There is no recursive call and deterministic local planners never enter this path. This is one bounded Generate → Inspect → Fix cycle, not an autonomous loop or visual-quality assertion.

## Workspace dependency graph and Agent context boundary

The workspace graph is a compiler output, not persisted workspace metadata. On every artifact revision Rune derives seven directed edge families from readable source: the first canonical Data artifact to every legacy metric consumer; the Data artifact resolved for each Query through `workspace_data`; an exact Query id to each three-argument scalar-metric consumer; an exact Data source id to its Chart artifact; an exact Query source id to its Chart artifact; each `{{ chart(...) }}` artifact to the Document or Presentation that embeds it; and an exact Document id declared by semantic HTML metadata or compatible Deck `origin` frontmatter to that presentation. A Query's first non-empty `-- rune:data "artifact-id"` line wins over workspace order; SQL imported without the directive retains the first Data as an explicit legacy mode. This makes `Data → Query → scalar metric → Document/Presentation`, `Data → Query → Chart → Document/Presentation`, and `Document → Presentation` first-class upstream chains. Invalid directives or metric syntax, absent Data/Query/Document sources, unsupported Query outputs, invalid Chart JSON, and unresolved metric/chart/origin ids become explicit graph issues rather than invented nodes. Edge order follows workspace identity, both endpoints are native navigation buttons, and the graph contains no copied result values or persisted runtime snapshots.

The `query-metric` edge also covers the optional four-argument form whose quoted fourth argument selects one zero-based Query result row. This adds runtime value selection, not a new graph edge family or persisted result snapshot.

Workspace Agent context starts at the selected artifact and any user-pinned artifacts, then traverses their graph components as an undirected discovery surface while inclusion remains directed and upstream-closed: a consumer is not sent unless every known source it requires is also sent. Unlinked files are never padded merely to reach a quota, but a user can deliberately bridge up to six disconnected files with native pin controls. Pins are ephemeral session capabilities: they are not written to local storage, `rune.workspace.json`, source, checkpoints, or the dependency graph, and folder Pull/reset clears them. A pin is a required root rather than a preference; its upstream closure is included atomically or the model path is disabled without silently dropping it. The pack retains original workspace order so legacy metric bindings and directive-free Queries keep their prior first-Data meaning, while explicit Query and Query-metric sources are preserved by identity; it then enforces seven files, 100,000 characters per non-selected file, and 180,000 characters in total.

The client first sends only edge kind, endpoints, bounded reference names, explicit pin ids, canonical sources, and eligible compiled legacy metrics. After the configured-provider handshake, Query metrics may additionally be explained by bounded, revision-identity-bound local result evidence; that evidence remains explicitly advisory rather than a new source or write capability. The API recompiles the graph from the supplied canonical sources, rejects unresolved upstream intent, requires an exact edge match, and reruns context selection from the selected id plus supplied pins. A disconnected artifact that cannot be reached from either root class is rejected before provider work, so pins cannot become cover for arbitrary hidden padding. The deterministic no-provider planner receives that same context pack without the evidence handshake, while collision-safe creation identity is still calculated against the full workspace. A valid model or local response remains only a proposed operation plan over the bounded pack. Apply stays bound to the full captured workspace revision and reruns every adapter, metric, Query-metric, and Chart dependency over all device artifacts; omitted downstream consumers therefore retain veto power over a patch that would break them. Context packing is a token/capability bound, never a weaker transaction boundary.

## Selection Agent boundary

Selection is an ephemeral capability over canonical source, not a second document model. The workbench records `artifactId`, the exact source revision, and native textarea `selectionStart`/`selectionEnd` offsets. UTF-16 is intentional because it is the browser control's coordinate system; Rune rejects ranges that split a surrogate pair, as well as collapsed, stale, out-of-bounds, or over-16,000-character selections. Selecting a valid range activates Selection scope and exposes format-aware deterministic quick commands, while editing, switching artifacts, Pull, reset, New, import, or a successful Apply invalidates the captured range.

The provider receives the full artifact for structural context plus the exact `selectedSource`, but it keeps the existing typed-operation vocabulary. After compiling those operations into `nextSource`, the server verifies that the complete source prefix before the selection and suffix after it remain identical; a semantically valid operation that crosses either boundary still fails the entire request. Review stores the same range and revision with the concrete patch. Apply repeats the prefix/suffix proof client-side before checkpoints or persistence, then runs the unchanged full-artifact adapter and whole-workspace dependency validation. This duplicated boundary protects against stale or tampered review data without granting the model a direct range-write primitive.

## Preview-to-source targeting boundary

The preview is a projection of canonical source, not an independent selection surface. Rune derives ephemeral `PreviewSourceTarget` records directly from the current artifact revision: visible Markdown headings start non-overlapping sections while fenced headings are ignored; top-level heading, paragraph, list, blockquote, fenced-code, GFM-table, and thematic-break nodes expose exact `document-block` ranges; individual list items, GFM header/body cells, strong/emphasis/delete spans, inline code, links, and images expose exact `document-fragment` ranges from the same CommonMark/GFM AST used by rendering; a quote-aware CSV scanner preserves multiline records, skips greedy-empty rows, and records every non-empty field token; a JSON value scanner finds exact top-level rows and property values without confusing escaped strings or nested delimiters; Deck targets exclude frontmatter and `---` separators while retaining each slide's metadata and source; and a valid Chart JSON artifact exposes its complete source as one `chart-spec` target. General targets contain a label, kind, index, and UTF-16 range; Document blocks record semantic block type, Document fragments record semantic fragment type plus table coordinates when applicable, and a data-cell target records its parsed row/column coordinate and exact column name. They are recomputed after every source change and never persisted as hidden ids.

All Preview-to-Source and diagnostic-to-Source actions first pass through `prepareSourceNavigation`. This React-free planner proves artifact existence, exact source revision, safe UTF-16 range or bounded diagnostic reference, then returns only an immutable effect plan: whether to change the active artifact, reveal Split, select a range, and activate Selection Agent. It does not read the DOM or change view, focus, history, Agent, persistence, or source. The Workbench is the sole effect executor. The reverse Source-to-Preview path likewise uses a pure candidate selector over rendered identity facts before the Workbench performs `scrollIntoView`; continuous Deck pages therefore need no special state machine or iframe messaging.

Document sections expose a keyboard-operable preview outline, each proven rendered Document block exposes separate native locate/edit controls, and each proven fragment is directly focusable with hover/focus/active feedback. A normal link activation selects its complete Markdown syntax; Command/Control-click retains ordinary navigation. Because metric values are shorter or longer than their `{{ ... }}` source tokens, `compileArtifactSource` emits a monotonic UTF-16 boundary map beside the compiled string; a rendered AST range is accepted only after this map returns to the exact canonical AST block or fragment range. Any Document block or fragment containing a Chart binding is withheld from the Document layer so the embedded Chart's category/value controls retain more precise cross-artifact provenance. Non-empty data cells expose native buttons, row numbers retain a full-record target, and Deck Markdown exposes a slide target strip outside its scriptless iframe. A CSV cell selects its complete lexical token, including enclosing quotes for quoted or multiline fields; a JSON cell selects the complete value token, including string quotes or a nested object/array. Empty CSV fields have no non-empty source range, missing JSON properties have no source token, and an object with duplicate keys exposes no cell target because its semantic value is ambiguous. Activation focuses the native source textarea, sets its exact selection range, and enters the existing Selection Agent scope. In the reverse direction, a source caret/selection resolves to the smallest containing fragment before its block and section; nested list items win by exact span, and a shared table delimiter prefers the cell beginning at that offset. No browser DOM range, model inference, or iframe message becomes authority. The normal 16,000-character selection bound still applies, and source edits invalidate the target through the same revision check. Legacy HTML slides and derived views without a proven one-to-one range deliberately expose no target; React charts and conservative SQL results use the compiler-owned provenance contracts below.

A proven Document block may also compile one visual write. `prepareVisualDocumentBlockEdit` re-resolves the complete target identity (`id`, index, label, range, block type, and heading depth) from the current artifact, normalizes only outer blank lines and newline style, and reparses the draft with the same CommonMark/GFM grammar. The draft must remain exactly one top-level node of the same type; a heading must retain its depth, every Rune binding token must remain byte-identical and ordered, and every byte outside the exact range must be unchanged. Heading, paragraph, list, quote, fenced-code, and table blocks are editable; thematic breaks remain navigation-only. The shared visual-write transaction then validates the full proposed workspace, preflights affected runtime consumers, rechecks the complete workspace revision, checkpoints the old artifact, and persists once. It returns the newly proven block range for synchronized source selection and active preview state; stale, empty, no-op, overlong, multi-block, type-changing, binding-changing, or downstream-invalid drafts write nothing.

A direct Data-cell target may additionally compile one visual write, but it never becomes a second table state. `prepareVisualDataCellEdit` first proves that the requested row, column, source offsets, and column name still describe the current revision. CSV accepts one bounded draft through the same automatic scalar parser as ordinary Data; flat JSON requires an explicit `string | number | boolean | null` type. Nested objects/arrays, ambiguous or missing values, non-finite numbers, no-ops, cells above 10,000 characters, stale offsets, and any replacement that changes bytes outside the exact lexical token fail closed. Rune reparses the complete source, proves the value round-trips and derives the new target range, then runs ordinary whole-workspace static validation and the complete impacted Data/Query/Chart runtime preflight against a captured workspace revision. Only after those checks does it checkpoint the previous source and perform one atomic device persistence; source, selection, preview, and Selection Agent context advance together. An explicit pencil button and Enter expose this capability, while a normal click retains exact source selection. Query results and Chart marks remain navigation-only even when their provenance points to the Data cell, preventing a derived projection from silently acquiring write authority.

A Document-section target uses the same shared visual-commit transaction without making rendered DOM canonical. The editor receives at most 16,000 characters from one current `document-section` target and renders its draft locally through the ordinary safe Markdown compiler. On Save, `prepareVisualDocumentSectionEdit` resolves the exact target id/index/label/range against the current source, preserves CRLF versus LF, and replaces only that range. A heading-backed target must retain exactly one visible heading at offset zero and the same heading level; its title and body may change. A preamble or heading-free body must remain heading-free. Fence-aware parsing prevents headings inside code blocks from becoming structure. Empty/no-op/oversized content, extra or missing headings, a stale range, a changed `{{ ... }}` live binding, or any byte change outside the selected section fails closed. The complete proposed workspace then passes ordinary adapter and dependency validation, receives a pre-edit checkpoint, and persists once before the new section range becomes both the left selection and right active target. Adding/removing sections, changing heading hierarchy, or changing metric/Chart dependencies remains explicit canonical-source or reviewed Agent work.

A Deck-slide target is likewise a revision-bound write capability for strict Deck Markdown. `prepareVisualDeckSlideEdit` re-resolves exact artifact/id/index/label/range identity, reads the existing parsed slide, and accepts only one supported layout enum, an optional single-line plain-text eyebrow of at most 100 characters, and a body of at most 16,000 characters. The draft preview synthesizes a temporary one-slide Deck from current validated frontmatter and compiles it through the same escaped no-script pipeline; it is never stored. Save normalizes the body to the artifact newline convention, serializes Rune-owned metadata, replaces only the exact target range, reparses the complete Deck, proves slide count and the new range, and preserves every `{{ ... }}` binding byte-for-byte and in order. Empty/no-op drafts, `---` separator injection, raw HTML, unsafe comment metadata, stale targets, unsupported layouts, cross-range changes, and invalid complete Decks fail closed. The shared visual transaction then validates the complete workspace, creates one checkpoint, persists once, and synchronizes the left selection and right target. Frontmatter, slide insertion/deletion/reordering, and binding changes remain source or reviewed Agent work. Semantic HTML uses the adjacent exact-section source-edit capability rather than this typed Deck serializer.

A valid Chart JSON artifact exposes its whole source as one `chart-spec` capability rather than mapping rendered bars back to JSON properties by DOM geometry. The standalone Chart toolbar keeps Data-point activation as provenance-based navigation, while Source selects the complete spec and Configure opens typed controls for all presentation/field properties except `source`. Field choices are derived from the exact bound Data columns or the conservative static output contract of the exact bound Query. The draft compiler preserves that source identity, sets `version: 1`, validates every value through `ChartSpecSchema`, emits deterministic indented JSON, and resolves the draft through current Data or revision-bound Query runtime before Save. Title/description bounds, bar/line/area, category/value, source/ascending/descending sort, currency/number/percent, six-digit color, and 1–20 marks are the only writable properties. Save re-resolves the complete current target, rejects no-op/stale/oversized/invalid specs, validates the complete dependency graph, executes the normal Chart runtime impact gate, checkpoints the old JSON, and persists once before both sides advance. Changing the Data/Query identity remains explicit canonical-source or reviewed Agent work because it changes dependency authority, not visual presentation alone.

## Cross-artifact chart provenance boundary

Direct-Data chart compilation attaches the zero-based parsed data-row index and exact category/value column identity to every valid datum before any ascending/descending sort or `maxItems` truncation. Query-backed compilation instead reads the current result cell's lineage: a direct projected field becomes `canonical Data artifact + source row + source column`, while a derived field has null provenance. The visible mark therefore retains only identities already proven by its source compiler, even when labels repeat or display order diverges from canonical source. React chart previews resolve each non-null provenance record through the current Data artifact's cell-target compiler. Missing artifacts, invalid current data, ambiguous JSON keys, missing cells, row-count mismatch, an out-of-range index, or a derived Query value leave only that visual part read-only instead of falling back to label/value matching.

Activating a provable chart label switches the workbench to the canonical Data artifact and selects the exact category token; activating a provable bar, line point, or area point selects the exact value token. A Query artifact is never treated as editable data merely because it rendered the chart. The workbench binds the Data artifact's current source revision, focuses the native textarea after the file transition, and enables Selection Agent. `data-chart-source-row`, the rendered label, order, formatted value, and geometry remain observability/presentation only. Standalone Chart views and React-rendered charts embedded in Markdown use native buttons for click, Enter, and Space activation; charts frozen into sandboxed Deck HTML, standalone HTML, DOCX, PPTX, or PDF stay non-interactive snapshots and gain no script bridge. The provider contract and write path are unchanged: the chart interaction merely supplies the existing source selection, after which server/client confinement, review, checkpoint, dependency validation, and atomic persistence still apply.

## Query-result provenance boundary

SQL is allowed to derive, collapse, duplicate, or combine rows, so a displayed value is never matched back by equality. Before DuckDB runs, Rune resolves the Query's exact Data binding, parses that CSV/JSON through the same adapter used by the grid, adds a temporary collision-safe import-order field, serializes those typed rows to an in-memory JSON file, and materializes `workspace_data` in that explicit order. The helper field is projected away before the user query and is never stored in source or exposed in results. This makes DuckDB's zero-based physical `rowid` agree with the preview target compiler even when a CSV contains quote-aware multiline records or greedy-skipped empty rows.

A conservative lineage compiler recognizes only one top-level `SELECT` over exactly one `workspace_data` relation. Filtering, ordering, limits, explicit aliases, direct identifiers, `*`, arithmetic, `CASE`, casts, and a bounded whitelist of scalar functions preserve one outer source row. The compiler injects a qualified `rowid` under a reserved hidden result name, executes the same bounded query once, removes that column before rendering, and maps projection positions rather than output values. A direct identifier produces `sourceRowIndex + canonical sourceColumn`; a calculated projection carries no cell lineage but keeps the row target. Case-insensitive source-column identity and column resolution must be unique, output arity must match the compiled projection map, and the hidden id must be a safe in-range integer. An empty source schema is rejected before starting DuckDB; source columns named `rowid` or the reserved result field disable lineage while preserving normal query execution.

`WITH`, aggregate functions, `DISTINCT`, `GROUP BY`, `HAVING`, JOIN/comma relations, set operations, pivot/unpivot, sampling, window/qualify, subquery or row-expanding projections, unknown functions, and any unrecognized shape still execute under the normal read-only SQL boundary but receive no target. Result row numbers become buttons only when their hidden id resolves to a current full-record target; direct result cells become buttons only when the row/column pair resolves to a current exact lexical cell. Computed cells remain plain table cells. Query state stores and compares the complete SQL source, data artifact id, and data source revision, so an old result is replaced by loading—not briefly rebound to edited data—before any click can grant Selection scope.

## Query-backed Chart snapshot boundary

A Chart may name either Data or Query in its strict `source` field. The Query first resolves an explicit `-- rune:data` id, or the legacy first Data when no directive exists. Workspace validation cannot execute DuckDB on every keystroke, so a conservative static compiler infers only a single outer `SELECT` output against that resolved schema: direct identifiers retain their names, a direct `*` may expand `workspace_data`, and derived projections must use an explicit `AS` alias. Set queries, duplicate case-insensitive output names, implicit derived names, ambiguous stars, or more than 256 outputs cannot become a Chart contract. This validates source identity plus category/value bindings and downstream patches without persisting query results or starting the worker.

Live preview then runs only the Query sources required by the selected Query, Chart, Document, or Deck and creates an ephemeral `WorkspaceQuerySnapshot`. The snapshot includes exact Query source, canonical Data id/source, bounded result, and cell lineage. A Chart accepts it only when both source revisions still match and the result is not truncated beyond the 500-row query boundary; edits immediately return the consumer to a loading state. Missing, failed, stale, or truncated snapshots produce an explicit non-chart state rather than silently reusing old values. Multiple consumers of the same Query share this revision-keyed runtime entry instead of launching independent executions.

Export is a separate deterministic consumer of the same contract. Before generating DOCX, PPTX, standalone HTML, or PDF, Rune reruns every Query source reachable from the target, refuses truncation, and passes those exact snapshots into the chart compiler. The exported chart is frozen and non-interactive, while canonical Query/Data/Chart sources remain unchanged. Thus a runtime result is evidence tied to source revisions—not a hidden persisted artifact and not a second source of truth.

## Query-backed scalar metric boundary

A Document or Deck can read one numeric Query output through the exact readable form `{{ metric("query-id", "column", "currency|number|percent") }}`. The parser accepts exactly three quoted arguments, an existing Query id, an output column proven by the conservative static Query schema, and one bounded display format. Legacy one-argument `metric("name")` bindings remain source-compatible and retain their first-Data semantics; the two forms are never silently rewritten into one another.

Static validation proves identity and schema without starting DuckDB, so a renamed Query column or missing bound Data vetoes the complete pending workspace mutation. Runtime compilation additionally requires a current `WorkspaceQuerySnapshot` for the exact Query and Data revisions, no 500-row truncation, exactly one result row, one unambiguous selected cell, and a finite numeric value. Missing, running, stale, multi-row, ambiguous, or nonnumeric results render as pending/error state and cannot be exported. Currency, number, and percent affect presentation only; they do not coerce Query cardinality or invent a value.

The preview coordinator runs the union of Query ids required by scalar metrics and charts, sharing one revision-keyed snapshot per Query. Office, standalone HTML, and PDF export independently rerun that same union and freeze formatted scalar values beside chart snapshots, so opening a preview is never a prerequisite for a correct handoff. Query results remain ephemeral runtime evidence and are not written to canonical source, local storage, checkpoints, folder manifests, or Git.

A `query-metric` dependency edge connects the Query directly to each consumer while the existing resolved Data-to-Query edge closes the upstream chain. Workspace Agent scope can introduce or retarget this cross-file reference only when the exact Query and Data are present in its verified context; Selection and File scopes must preserve the before/after Query-metric signature. The default workspace uses an explicit `regional-summary.sql` aggregate for numeric KPIs, while keeping one legacy `top_region` binding as a visible compatibility example.

## Local artifact creation boundary

Creating a canonical artifact follows the same source-first rule as import and Agent writes. The user chooses Document, Data table, Query, Chart, or Presentation and supplies a bounded title. A deterministic factory produces either the smallest core source—one Markdown heading, an empty `Item,Value` CSV schema, or strict Deck Markdown frontmatter plus one cover slide—or a complete typed dependency source. Query requires one exact Data id and starts with a quoted `-- rune:data` directive plus `SELECT * FROM workspace_data;`. Chart requires one exact Data/Query id, exact category/value fields, a bar/line/area mark, and a number format, then starts as complete strict Chart JSON. Unicode titles stay readable, while filenames and ids are normalized, portable, bounded, case-insensitively collision-safe, and protected from reserved device names. Unicode letter/number ids are also valid in formatted `{{ chart(...) }}` references. The workspace is capped at 50 artifacts to match the folder port.

Creation is prepared from the current workspace, validated through every adapter and dependency compiler, and only then persisted. The dialog exposes exact source candidates and fields, resulting filename, language, and complete initial source; its title field receives initial focus, its type choices use radio semantics, focus is trapped, and Escape cancels. A new Chart may optionally target one existing Markdown Document or Deck Markdown presentation. Rune then appends a readable binding to that consumer, checkpoints its pre-change source, validates the combined patch-plus-creation graph, and commits one device write. Confirmation selects the new artifact and leaves a connected source folder untouched until the user explicitly Pushes. Invalid titles, stale/missing sources or fields, duplicate embeds, an invalid current workspace, name/id conflicts that cannot be resolved, or storage failure produce no partial artifact.

Workspace Agent creation uses the same factory rather than a parallel model-owned path. The compiler prepares each template against the evolving workspace identity set, runs zero to eight typed edits, and returns the resolved artifact only after schema validation. A source or Chart reference may use an earlier action-local handle; direct artifact references remain confined to original visible context, and patches still cannot target a just-created file. This supports a four-action Data → Query → Chart → Document/Presentation chain without exposing collision-sensitive ids. Multiple same-title creations receive deterministic suffixes, handle-to-id pairs stay compiler-local, and mixed patch/create plans enter one full-workspace transaction. Human New and Agent Create differ only before review: the dialog supplies explicit controls and optional atomic embedding, while the Agent supplies bounded typed intent and ordered references. Both end at the same canonical artifact, dependency/runtime validation, atomic persistence, folder-Push boundary, and later Office export path.

## Shared metrics and lineage

Markdown Documents, semantic HTML Presentations, and compatible Deck Markdown can reference a legacy Data-derived value with `{{ metric("total_revenue") }}`, a Query scalar with `{{ metric("regional-summary", "total_q2_revenue", "currency") }}`, or a reusable view with `{{ chart("regional-revenue-chart") }}`. The dependency compiler derives legacy metrics and direct Chart models from canonical CSV/JSON, and Query-backed metrics and Chart models from current revision-bound SQL snapshots, then substitutes only at render time. Sources stay readable and one Data or Query edit invalidates every dependent projection. Each compiled view exposes its source artifact and reference count. SQL and Chart artifacts expose their canonical lineage, while the workspace graph exposes current dependency topology without persisting a second source of truth. Imported semantic HTML keeps the one-argument binding syntax for compatibility.

## Declarative chart runtime

A `.chart.json` artifact is a strict, versioned view contract: title, description, Data-or-Query artifact id, exact category/value output columns, a `bar`, `line`, or `area` mark, sort policy, number format, validated color token, and a 1–20 mark limit. It contains no code. Bar geometry compares absolute magnitude against the visible maximum. Line and area geometry preserve the explicit post-sort sequence, space finite points uniformly, and normalize the visible minimum/maximum into a bounded vertical position; an all-equal series stays centered rather than inventing a range. Area additionally fills from that exact point path to the bounded plot baseline. For Data, the local compiler parses canonical CSV/JSON directly. For Query, workspace validation uses the static output contract while rendering requires a current runtime snapshot. Both paths validate every row, sort and format values deterministically, retain exact point/bar provenance, and produce one shared chart model.

“Deterministic” includes display text, not only source and data order. Compact `Intl.NumberFormat` output differs across JavaScript/ICU implementations—for example one runtime can emit `$970K` while another emits `$970.00K` for the same options—so it is not part of Rune's server-render contract. A small shared formatter now owns grouping, K/M/B/T selection, two-decimal rounding with trailing-zero removal, currency/sign placement, and fixed one-decimal percentages. Metrics, React charts, static Deck HTML, and Office/PDF snapshots all consume those exact strings. SSR and hydration therefore compare compiler output, not two engines' locale opinions; locale-aware author-controlled formats can be added later as explicit source metadata rather than ambient runtime state.

Markdown renders that model as React elements: bar, line, and area labels expose category buttons, while bars and SVG-overlaid line/area points expose value buttons only when current canonical provenance resolves. Both semantic HTML and Deck Markdown compile to bounded static HTML before the Slides adapter replaces chart references with the same escaped chart model and assigns `srcDoc`; line and area series use deterministic inline SVG without scripts, labels and titles cannot become markup, and every iframe remains scriptless. Whole-workspace patch validation recompiles every chart after a data or schema edit, so renaming a bound column cannot silently break downstream reports or presentations.

## Presentation compilers

The default canonical presentation format is semantic `.html` produced by Rune's `presentation-v1` factory. Its `<main>` metadata and outer-section pages are readable and compiler-proven, and exact section editing or Agent operations preserve the complete surrounding source. Semantic HTML presentations are limited to 120,000 source characters and 40 slides.

Compatible `.deck.md` remains a strict `version: 1`, `title`, `theme`, `ratio`, and `lang` contract; slides are separated by `---`; optional `layout` and `eyebrow` comments are validated against bounded values. The body supports headings, paragraphs, lists, tables, inline emphasis/code, local-image references, and metric/chart references. Decks use the same source and slide limits. Package import and semantic HTML handoff may use this model only as an immutable bounded intermediate; it is no longer the canonical output of PPTX/ODP import.

Each compiler owns the 16:9 frame, design tokens, layout classes, and page numbers for its format. The Deck branch HTML-escapes source text and rejects raw HTML; the semantic branch requires one proven main/outer-section structure, rejects scripts, and builds independent no-script sandboxes. Proven outer sections may be edited as exact canonical source, but neither branch grants iframe DOM, CSS inspection, or browser-corrected structure any write authority.

## Browser-local Office semantic import

Modern `.docx`, `.xlsx`, and `.pptx` files are Open XML ZIP packages. Rune lazily loads a small package/XML adapter only after the user chooses one, extracts bounded XML plus explicitly related `word/media` or `ppt/media` parts, and never uploads the original file. DOCX paragraphs, heading styles, run emphasis, links, numbering, tables, and supported embedded images become Markdown. Every visible XLSX worksheet becomes an independent CSV artifact with shared/inline strings, booleans, numbers, common date formats, and cached formula values. Ordered PPTX slides use placeholder titles, body paragraphs, bullets, tables, and supported pictures to produce a validated temporary Deck; after image finalization, that exact model compiles into the committed `presentation-v1` semantic HTML artifact.

This is intentionally semantic, not round-trip or pixel fidelity. Supported PNG/JPEG/WebP/GIF bytes pass the shared magic-byte, dimension, size, and SHA-256 asset port; DOCX keeps readable image positions, while PPTX uses one primary image per compatible slide and adjacent bounded image slides for additional or table-conflicting pictures. Invalid, missing, external, oversized, or geometrically ambiguous media is never fetched or guessed and produces an explicit warning. Comments in DOCX, hidden sheets and live formulas in XLSX, and charts/animation/master styling in PPTX remain omitted or flattened; legacy binary `.doc/.xls/.ppt` and macro-enabled formats are outside this adapter. A batch import resolves duplicate names/ids and validates every new artifact plus the complete dependency graph, but remains a pending transaction. The review surface lists every generated filename, all fidelity warnings, and at most 12 lines/1,600 characters from each source. The full validated sources and prepared image assets remain in memory and are not written until the user confirms.

The pending transaction retains the exact base workspace object. Import is disabled before device hydration and conversion is single-flight; if editing, folder pull, reset, or another operation replaces the artifact array while conversion runs, confirmation rejects the stale transaction. When a reviewed conversion contains images, the review requires exact closure between imported `rune-asset` references and deduplicated prepared bytes. Confirmation stores assets first and performs the device workspace write second; a failure at either boundary deletes only assets newly created by that attempt. Cancel, parse failure, stale context, validation failure, or quota failure keeps the previous workspace object unchanged and never exposes a partial batch.

The compressed file limit is 12 MB. Package reads allow at most 2,000 entries, 6 MB per XML part, and 24 MB expanded XML in total; DTD/entity declarations and path traversal are rejected. Output is capped at 200,000 characters per artifact and 500,000 across one workbook, with additional semantic limits of 10,000 Word blocks, 10 worksheets, 10,000 rows, 256 columns, 50,000 spreadsheet cells, and 40 slides. Large-file conversion can move behind the same port into a Web Worker later without changing its output contract.

## Browser-local PDF semantic import

PDF input follows the same review-first transaction but has a separate lazy port. Choosing a `.pdf` dynamically loads PDF.js plus its same-origin worker; neither is part of the initial workbench chunk. Rune copies the input bytes, requires a PDF header in the first 1,024 bytes, disables eval, streaming, range and auto-fetch behavior, stops on parser errors, and never uploads the file. Password-protected files fail with an instruction to import an unlocked copy. PDF JavaScript is detected only to produce an omission warning and is never executed.

The adapter records metadata title, page geometry, selectable text fragments, annotations, outline count, and JavaScript presence. It groups fragments into geometry-aligned lines, handles CJK joining and dominant right-to-left order, identifies repeated top/bottom headers and footers, estimates body font size, and converts conservative heading, bullet, numbered-list, paragraph and hyphen joins into one Markdown Document. Every page retains a `<!-- PDF page N -->` provenance marker. Raw braces are encoded before validation so a PDF cannot fabricate Rune metric or Chart bindings.

Pages with no selectable text trigger a separate consent boundary before any page pixels are read. Rune shows the exact detected scan-page ranges per PDF; the user may narrow them and explicitly chooses English, Simplified Chinese, or both. Whole page is the default. Opening setup still reads no pixels; a separate preview action may render the chosen page locally so the user can drag one paper-aligned rectangle or enter normalized Left/Top/Width/Height percentages for that page. Each selected page owns an independent optional region, and reset returns it to whole-page recognition.

Only the preview action or final recognition authorization lets PDF.js render a page. Recognition uses bounded browser canvases (2,400-pixel long edge and eight-megapixel ceiling) while one Tesseract worker processes pages sequentially; a selected region crops that canvas before Tesseract receives it. The conversion port reopens the PDF, revalidates exact detected pages plus finite in-page regions of at least 2% width and height, and rejects region references to unselected pages before OCR. Worker, WASM core variants, and compressed language data are bundled on the same origin rather than fetched from a third-party CDN; the runtime may cache language data in IndexedDB, but page images and recognized text never leave the browser. The operation exposes page/stage progress and can be stopped; cancellation releases page, canvas, loading-task, and worker resources and performs no workspace write.

OCR output is untrusted transcription, not canonical fact. Every recognized block keeps `<!-- PDF page N · OCR confidence N% -->`, adding the normalized crop when a region was selected, a visible whole-page/selected-region verify-against-original disclosure, and a separate page-level rounded average-confidence warning in the final import review. Empty recognition remains explicit. The same brace encoding prevents OCR output from fabricating Rune metric or Chart bindings. A user cannot select a page that already has selectable text or lies outside the analyzed document, and conversion reopens and revalidates the PDF so stale/mismatched requests fail closed.

This is semantic extraction, not visual reconstruction. Reading order is approximate; images, exact fonts/layout, tables, columns, links, comments, form controls and bookmarks are omitted or flattened with review warnings, and OCR may omit, reorder, or misread content. The input limit is 12 MB, with at most 200 pages, 100,000 text fragments, eight million rendered pixels per OCR page, and 200,000 generated Markdown characters. The resulting artifact then passes the normal collision resolution, workspace validation, stale-context check and single confirmed device write used by compatibility import.

## Browser-local OpenDocument semantic import

ODT, ODS, and ODP use a separate lazy browser port rather than pretending that every ZIP-based office format has the same object model. Rune requires the extension-specific MIME value, requires the first ZIP entry to be an uncompressed `mimetype`, and verifies the root and `content.xml` entries in `META-INF/manifest.xml`. Only `content.xml`, optional `styles.xml` and `meta.xml`, the manifest, and bounded referenced `Pictures/` bytes are decoded; package media is never interpreted as executable content. DTD/entity declarations, encryption metadata, duplicate or traversing paths, oversized parts, scripts, and macros fail or become explicit non-executed warnings.

ODT headings, paragraphs, inherited emphasis, HTTP/mailto links, lists, tables, and supported `Pictures/` image references become source-safe Markdown. ODS visible tables become separate CSV artifacts while preserving finite numeric, boolean, date, time, string, currency, and percentage values; formula cells contribute cached values only, formula-leading text is apostrophe-prefixed, and standard large repeated empty rows or columns are skipped without allocating them. ODP page order, title/body text, bullets, tables, and supported pictures enter the same temporary Deck proof and committed semantic HTML path as PPTX under one primary visual per page. Image bytes use the shared content-hash finalizer; comments, tracked-change history, hidden sheets, live formulas, objects, charts, notes, animation, crop/overlap, and exact layout are omitted or flattened with review notes. Braces are encoded before canonical validation so imported content cannot manufacture Rune bindings.

The compressed input limit is 12 MB, with at most 2,000 ZIP entries, 6 MB per XML part, 24 MB decoded XML, 200,000 characters per artifact, and 500,000 characters per ODS batch. Semantic limits match the surrounding adapters: 10,000 text blocks or rows, 256 columns, 50,000 cells, 10 visible sheets, and 40 slides. The converted batch enters the same collision resolution, full-workspace validation, stale-context check, keyboard-accessible review, and single confirmed device write as OOXML and PDF import.

## Browser-local Office semantic export

The reverse adapter is also lazy and browser-only. Markdown block/inline structure becomes a deterministic DOCX package with main document, styles, numbering, tables, and restricted external hyperlink relationships. CSV/JSON is parsed through the canonical data adapter and becomes one values-only XLSX worksheet with typed number/boolean cells, inline strings, a frozen header, styles, and autofilter. Validated Deck Markdown becomes an ordered 16:9 PPTX with one slide part per source slide plus the required presentation, slide master, slide layout, theme, and relationship graph. A semantic HTML Presentation first crosses the immutable reviewed Deck projection described above; that projection is never written back. Document and presentation metrics compile from the current workspace, with referenced Query scalars rerun against their exact Data revisions before packaging; canonical source itself is never rewritten.

Export is semantic rather than pixel-exact. DOCX does not synthesize comments or advanced page design; reviewed Rune images become explicit internal media relationships. XLSX deliberately emits no formula nodes and does not infer workbook formulas/charts from CSV or JSON. A standalone Chart directive resolves through the same strict Chart model used by live preview; Query-backed charts first rerun the exact Query/Data revisions and provide that snapshot to the resolver. DOCX renders a frozen bar as a selectable three-column semantic bar table and a line as a semantic trend-direction table. PPTX emits editable text plus native track/bar rectangles or line segments, circles, labels, and values inside the slide shape tree. The Office copy is intentionally static and its fidelity report names the source because it no longer has Rune's live binding. Inline chart directives retain an omission marker, PPTX includes at most one chart per slide, and a chart takes layout priority over a table on the same slide.

PPTX otherwise preserves title/body text, bullets, tables, order, theme colors, basic layout, and one verified content-hash image as the slide's primary visual. The image becomes a package media part with an explicit per-slide relationship, original aspect ratio, deterministic geometry, and no network target. Unsafe non-HTTP links cannot become hidden active package relationships. XML text is sanitized, formula-looking spreadsheet values remain inline strings, and ZIP timestamps are fixed so identical source and workspace context produce identical bytes. Shape bounds are tested against the declared 16:9 canvas, and release QA renders a chart-first or image-first PPTX through an independent installed Office handler instead of trusting Rune's own parser.

The export review retains the exact base workspace reference, generated bytes, target filename/MIME, and all fidelity notes. A changed workspace rejects confirmation; cancel produces no download, and confirmation creates one object URL without changing drafts or checkpoints. DOCX is capped at 200,000 source characters and 10,000 blocks; XLSX at 2,000,000 source characters, 10,000 rows, 256 columns, and 50,000 cells; PPTX inherits the 120,000-character/40-slide Deck contract. Every final package is capped at 12 MB. Import and export share the pinned ZIP library but remain separate dynamic entries, so no new service or initial-load dependency is introduced.

## Browser-local OpenDocument semantic export

The ODF adapter mirrors the same canonical-source handoff without sharing OOXML-specific relationships. Markdown Documents compile to ODT headings, paragraphs, inline emphasis, restricted links, lists, semantic tables, code/quote styles, and current Chart data tables. CSV/flat JSON compiles to one typed, values-only ODS sheet; formula-looking text remains a string and no OpenFormula expression is generated. Compatible Deck Markdown, or semantic HTML after the immutable reviewed Deck projection, compiles to ordered 16:9 ODP pages with native text, bullets, tables, and selectable current Chart data tables. Query-backed metrics and Charts use the same exact revision-bound local snapshots prepared before packaging, so exported values are frozen evidence rather than a hidden runtime.

Each output is an ODF 1.3 ZIP with an uncompressed first `mimetype` entry, `content.xml`, `styles.xml`, `meta.xml`, and `META-INF/manifest.xml`. Verified Document and Deck images become `Pictures/` entries with exact MIME manifest records and aspect-fit drawing frames. ZIP timestamps and XML order are fixed for byte determinism; XML characters are sanitized; hyperlinks are restricted to HTTP, HTTPS, and mailto; and no script, macro, formula, external media dependency, or live binding is emitted. The package is capped at 12 MB and uses the shared export review's captured workspace reference and explicit confirmation. Exact pagination, comments, tracked changes, formulas, filters, animation, notes, and advanced master styling stay explicit fidelity notes. Release QA validates every XML part against the official OASIS ODF 1.3 Relax NG schemas, imports each result back through Rune, and checks the installed system handlers; ODT and ODS are additionally opened through Word and Excel, while ODP relies on schema/round-trip validation when PowerPoint automation is unavailable.

## Browser-local standalone HTML export

Deck Markdown can also cross the compatibility boundary without an Office package or hosted share link. The lazy adapter follows one deterministic pipeline: `canonical Deck → collect metric/Chart Queries → run exact snapshots → compile legacy and Query metrics → resolve Chart models → validate/render escaped static HTML`. It reuses the exact compiler, theme, automatic numbering, and chart renderer used by preview, then wraps the result in a complete UTF-8 document with inline styles and print rules that make every 16:9 slide one page. The canonical `.deck.md`, `.sql`, Data, and Chart JSON sources remain unchanged.

The result is deliberately a frozen handoff rather than a second Rune runtime. It contains no scripts, editor controls, Agent surface, checkpoints, live bindings, or external resources. User-controlled metadata and content are escaped by the Deck compiler. Every referenced local image is reverified and converted to an approved `data:image/*;base64` URL only for this portable handoff; the canonical source never receives base64. The export boundary rejects script, iframe, object, embed, link, and every `src`/`href` value not equal to one of those exact generated image URLs. All bindings and assets must be resolved, the final encoded file is capped at 12 MB, and identical workspace context produces identical bytes. This allows the receiver to open, archive, present, or print to PDF using an ordinary browser without a server, account, asset host, or package dependency.

HTML, Office, and PDF outputs share one review transaction contract: generated bytes, target kind, filename, MIME type, fidelity notes, and the exact base workspace reference. Preparing an output is single-flight, does not write device state, and loads only its destination adapter. If editing, Pull, reset, or another transaction replaces the workspace before confirmation, download is rejected and must be regenerated. Explicit confirmation creates one object URL; cancel leaves drafts and checkpoints untouched. Release QA renders HTML and PDF through independent system handlers so those exporters are not validated only by Rune's own preview.

## Browser-local fixed PDF export

Markdown Documents and Presentations can cross the final handoff boundary directly, without a browser print dialog, server renderer, account, or upload. The lazy adapter follows the same reviewed snapshot pipeline as Office and HTML export, then uses a browser-compatible PDF writer. Documents compile into fixed A4 pages with semantic headings, paragraphs, lists, quotes, code, bounded tables, headers, footers, and page numbers. Semantic HTML first crosses the immutable Deck projection; both presentation formats then compile into one 960×540 16:9 page per validated slide while retaining Rune theme, layout, scalar metrics, tables, and vector bar, line, or area charts. Data artifacts continue to use XLSX rather than inventing a paginated spreadsheet contract.

The PDF is a frozen visual handoff rather than a second editor format. Query metrics require the exact current one-row finite snapshot, Query-backed Charts require the exact current non-truncated snapshot, and every chart becomes local vector geometry. Verified standalone Rune images in Documents, semantic HTML Presentations, and compatible Decks are decoded locally and embedded into bounded aspect-fit frames; unsupported ordinary Markdown or external HTML images remain visible omissions. Links remain readable but are not active; fixed frames visibly shorten or omit overflowing content and record a fidelity warning. Animation, speaker notes, editable slide objects, live bindings, comments, forms, and JavaScript are not generated. Canonical Markdown, HTML, Deck, SQL, Data, and Chart JSON stay byte-for-byte unchanged.

Rune bundles the OFL-licensed Unifont WOFF2 asset and embeds the glyphs used by text that cannot use the standard PDF font, so Chinese and other supported Unicode do not depend on network or receiver fonts. Unsupported characters become visible question marks with a review warning rather than black boxes. Source is capped at 200,000 characters, the font asset at 4 MB, and the final file at 12 MB. Metadata dates are fixed, identical inputs produce identical bytes, and release QA loads the file with an independent PDF parser, verifies page geometry and the absence of JavaScript/forms/encryption, renders every page through Poppler, and visually inspects the resulting images before handoff.

## Browser-local SQL runtime

The Query adapter treats `.sql` as canonical source and lazily starts DuckDB-Wasm only for a Query preview, a Query-dependent export, a configured Workspace Agent evidence handshake, or an Agent Data/Query runtime-impact preflight that actually has an impacted Query to execute. The optional first non-empty line must be exactly `-- rune:data "artifact-id"`; its JSON-quoted id supports Unicode while duplicate, displaced, malformed, missing, or non-Data targets fail closed. Directive-free imported SQL retains the first Data as a visibly labelled compatibility mode. Before each run, the resolved CSV/JSON is parsed into typed canonical rows, serialized to a temporary in-memory JSON file with explicit import order, and materialized as `workspace_data`. Rune accepts one `SELECT` or `WITH` statement, wraps it as a subquery, and requests at most 501 rows so the UI can display 500 and report truncation. Queries are serialized to avoid worker races, while exact query/resolved-data revision gating keeps stale results non-interactive as source changes.

The same lazy coordinator serves Query-backed scalar metrics and Charts in standalone, Document, and Presentation previews across semantic HTML and compatible Deck Markdown. It keys each execution by required Query id plus exact Query/Data sources, shares one result across current consumers, and keeps all snapshots in component runtime state only. This preserves the browser-local zero-infrastructure boundary while letting SQL become a reusable view source.

The npm wrapper is pinned to a stable version, and matching worker/Wasm binaries are loaded from a version-pinned CDN URL. The row-preserving lineage subset is a local compiler, not a DuckDB extension or hosted service; unsupported query shapes simply keep their normal read-only result. This keeps the deployed application small and infrastructure-free while rows remain inside the browser. A future offline distribution can serve the same pinned binaries from an asset origin without changing the query contract.

## Task-first operating-review compiler

The operating-review entry is an orchestration layer over existing canonical compilers, not a privileged Agent path. Its input contains one exact Data artifact id, exact case-sensitive category and finite-number fields, aggregation, Chart mark/format, plain-text title/period/focus, audience, locale, and a unique non-empty set of Document/Slides deliverables. It creates a readable identity-bound Query, a Query-backed Chart, and one or two source-native deliverables; a requested Presentation is semantic HTML by default. Generated titles pass the normal collision-safe artifact factory; generated bindings pass the normal whole-workspace validator. The compiler never writes conclusions that were not present in the input or evidence.

`prepareOperatingReviewEvidence` is also the only mapping-preview port. Its output separates full-scope accounting (`matchedRowCount`, `groupCount`) from the bounded evidence rows that may reach a model. The dialog may display a smaller projection, but it cannot recompute or extend that evidence. This keeps mapping feedback, generated Query order, Chart labels, and model capability ids on one deterministic source of truth.

The workbench captures the complete source revision before preparation, compiles the full creation list, repeats the whole-workspace mutation check, and runs the existing browser-local runtime-impact preflight. A stale revision or any SQL/Chart/downstream failure returns no pending change. Success produces the same transaction map, per-file source diffs, runtime evidence card, explicit Apply, and atomic device persistence as every Workspace Agent change; the task layer receives no direct persistence capability. Cancel and every error path leave the caller's artifacts and input immutable. Seven deterministic fixtures cover bilingual chains, exact ids/bindings, invalid sources/field case, nonnumeric values, duplicate deliverables, case-insensitive collisions, and frozen-input success/failure paths.

### User-confirmed delivery evidence

An applied mutation proves that Rune wrote a valid proposed workspace; it does not prove that a person could use the result. After a saved operating-review Document or Slides artifact is actually downloaded or written to its connected folder, the workbench may request one optional rating: `ready`, `minor-edits`, or `not-ready`. The confirmation must resolve an exact saved workflow, an exact applied run, and the workflow's exact Document or Slides id. Stopped runs, foreign artifacts, unsupported download targets, and incoherent folder/download method pairs fail closed.

The device record contains only version, deterministic `runId + artifactId` identity, confirmation time, run id, artifact id, method, target format, rating, task duration, and a Web Crypto SHA-256 fingerprint of the handed-off canonical source revision. It never stores source text, prompt, Query rows, filename content, or credentials, and it never emits remote telemetry. Reconfirming the same run and artifact replaces its earlier judgment; each workflow retains at most twelve newest records. Older saved tasks normalize a missing delivery list to an empty list.

Delivery summaries treat `ready` and `minor-edits` as usable but preserve their separate counts. UI metrics and per-run history derive from normalized records instead of copied counters. This evidence can measure the product's stated task threshold on one device, but it does not replace consented user research, retention, payment, or externally validated outcome evidence. Saved workflow locale normalization and Deck `lang` metadata both use the complete nine-locale registry so a French, Spanish, Russian, Arabic, Japanese, or Korean task cannot disappear or fail after creation.

## Explicit interface localization

Locale is an explicit UI dependency, not an ambient browser input. The server renders one stable English LTR workbench and never reads `navigator`, local storage, time, or runtime locale data during SSR. After hydration the setup flow recommends a device language, restores the confirmed preference, updates root `lang` and `dir`, and passes `RuneLocale` into the workbench, review dialogs, dependency/transaction maps, and the complete Document/Data/Query/Chart/Presentation preview tree. The registry contains Simplified Chinese, Traditional Chinese, English, French, Spanish, Russian, Arabic, Japanese, and Korean; every greeting is derived from that same registry. Arabic reverses UI flow while canonical source, code, URL, model-id, API-key, and data-grid surfaces keep explicit LTR boundaries. This prevents a confirmed language from falling back when the user enters a professional editor or review step without reintroducing server/client text divergence.

`runeUICopy(locale)` is the typed synchronous contract for normal product copy after its locale is ready. English and Simplified Chinese are built in; Traditional Chinese conversion data and French, Spanish, Russian, Arabic, Japanese, and Korean each compile to one independent static same-origin module. The Workbench awaits the stored, detected, or newly selected locale before changing locale state, and task routes await the validated request locale before invoking a synchronous compiler. An unloaded deferred locale fails loudly rather than silently returning English; concurrent loads coalesce and failed loads remain retryable. CI regenerates and checks the development-time machine catalog plus human-reviewed overrides against each runtime module, then enforces a 750 KB minified Workbench-entry budget. Runtime makes no translation request. Dynamic counts, filenames, targets, bindings, and review summaries remain functions rather than DOM replacement; deterministic Agent suggestions and high-frequency status text reuse the same loaded boundary without rewriting stored state. Raw parser, provider, SQL-runtime, and adapter fidelity evidence may remain in its originating language: those strings are technical facts and need stable error codes before localized rendering. See [ADR 0032](decisions/0032-interface-locales-load-before-synchronous-use.md).

Appearance is likewise explicit presentation state. SSR fixes `data-theme="mist-blue"`; hydration may restore one validated id from `mist-blue | sage | lavender | deep-blue | cosmic-orange` and writes only that enum to local storage. Theme tokens may affect focus, action, selection, and material atmosphere, while the independent vermilion Rune mark remains stable. Neither locale direction nor appearance state may change Artifact source, checkpoints, dependency identity, exports, or Agent context.

The desktop source/preview ratio follows the same presentation-only boundary. Its persisted value is accepted only from 35–65%, defaults to 44%, and becomes complementary CSS grid tracks without entering workspace persistence. A semantic vertical separator supports pointer drag, Arrow keys, Shift acceleration, Home/double-click reset, localized value text, and RTL-aware physical direction; below the desktop breakpoint it disappears and the existing stacked layout remains authoritative. Resizing never changes source-linked target identity, preview scroll authority, or canonical state.

## Checkpoint log

Device history is an append-only, per-artifact list of source snapshots. Applying a file or workspace Agent mutation records every patched pre-change source before the atomic write; a newly created artifact has no prior source to checkpoint. ⌘S records an explicit manual snapshot; restoring an older snapshot first records a safety checkpoint of the current source. Consecutive identical snapshots are deduplicated, malformed storage is ignored, and each artifact retains at most 24 checkpoints within a 500,000-character budget. Sources over 200,000 characters require export instead of a localStorage snapshot, and quota failures remain visible in the save indicator. Both drafts and checkpoints share the local workspace storage envelope, so refresh no longer destroys the normal undo boundary.

## User-owned folder storage port

The optional File System Access adapter maps each artifact to its existing readable filename and writes one `rune.workspace.json` manifest containing only version, order, ids, kinds, names, languages, and—when present—bounded asset metadata. Source and binary bytes never move into the manifest. Source-only version 1 remains readable. Version 2 maps each exact referenced image id to name, MIME, and size; the corresponding bytes live at `.rune-assets/<sha256>.<ext>`. A folder without a manifest can be scanned by supported extension and receives stable filename-derived ids only when it contains no `rune-asset:` references; hidden files, subdirectories, and unsupported formats are otherwise ignored.

Once the user has granted a session-scoped directory handle, the workbench monitors only metadata for bounded Rune source files and `.rune-assets` entries. It uses recursive `FileSystemObserver` notifications when the runtime exposes that capability and otherwise compares a stable name/size/last-modified fingerprint every three seconds. A change only marks the connection as changed and points to the existing Pull action; it cannot read source into canonical state, create a checkpoint, or write a folder by itself. Confirmed Rune Pushes temporarily mute the notification path while the observer or poller advances its baseline. Losing observation permission is visible and requires reconnecting. See [ADR 0029](decisions/0029-folder-observation-never-bypasses-reviewed-pull.md).

Folder reads are bounded to 50 artifacts, 2 MB per source file, 8 MB source total, 40 images, 8 MB per image, and 64 MB image total. Rune parses every source, validates unique identity, recompiles metrics/charts, requires exact asset-reference closure, and repeats image magic-byte/hash checks before offering replacement. An accepted Pull stores/deduplicates assets, checkpoints every current artifact, then uses one local source-persistence write; failure removes only assets created by that Pull. Push is deliberately manual and confirmed: it first rereads and verifies every referenced IndexedDB asset, writes `.rune-assets` before source, overwrites only matching names, never deletes unrelated files, and writes the manifest last. Browser filesystem writes do not provide a cross-file transaction, so an interrupted Push reports the exact file or asset where it stopped and never claims atomicity.

## Device task evidence

Operational task evidence is separate from portable task recipes and canonical source. `task-evidence.ts` owns one versioned, bounded device ledger for registered task runs and post-handoff usability judgments. It imports task identity and source-revision utilities, but no React, browser storage, provider, compiler, credential, or mutation API. The workbench supplies the only persistence capability.

Operating Review and Document-to-Presentation both write an applied run in the same local-storage transaction as their validated source mutation, checkpoints, and source-owned task recipe. The record contains exact task/source/output ids and portable revisions, actual planner provider, provider-reported token usage, bounded runtime-impact counts, and elapsed time. Cancellation, stale revision, validation failure, runtime failure, and persistence failure use the same stopped-record path, but evidence persistence is best-effort and cannot authorize or rescue a source write. Twenty-four newest runs are retained.

A delivery judgment is offered only after an exact task output is downloaded or written to a user folder and only while the current task source and every output still match that applied run's recorded revisions. The all-output check is required because an Operating Review's Query or Chart can change its rendered report without changing report Markdown. Confirmation adds a SHA-256 fingerprint for the handed-off output, handoff target/method, rating, and elapsed time; stopped runs, foreign outputs, changed revisions, invalid method/format pairs, duplicate ids, malformed hashes, and oversized values fail closed. Reconfirming one run/output replaces the prior judgment and twenty-four newest outcomes are retained.

Storage version 3 is the sole writer for new evidence from both focused tasks. Valid v1/v2 ledger facts migrate forward without invented scores. Older per-workflow Operating Review runs and deliveries lack source/output revisions, so they remain visible only as read-only earlier device records: Rune neither appends to them nor treats them as current success or delivery proof. The ledger stores no canonical source, prompt, model response, Query evidence, credentials, user identity, or background telemetry. Source-owned recipe fields remain inside readable Artifacts; device execution facts remain in the ledger. See [ADR 0013](decisions/0013-task-results-use-a-shared-device-evidence-ledger.md), [ADR 0014](decisions/0014-task-evidence-authority-migrates-forward-once.md), and [ADR 0017](decisions/0017-human-evaluation-requires-explicit-provenance.md).

`pilot-evidence.ts` is a read-only export consumer of the normalized ledger, not a second evidence owner. It requires an explicit export time, emits deterministic JSON under 128 KB, and refuses an empty valid ledger. Internal run/output identities are replaced with package-local `run-001` / `output-01` labels; timestamps are reduced to dates; provider labels collapse to `local` or `configured-model`; source/output ids, filenames, paths, revision tokens, SHA-256 delivery fingerprints, content, prompts, responses, Query rows, credentials, and identity never enter the package. The only retained facts are bounded task status and impact counts, duration, optional token counts, handoff format/rating, and complete normalized authorized/redacted evaluations. The Workbench can present and download these bytes but cannot alter them, and a ledger identity change while the dialog is open invalidates the review. No API, upload, telemetry, filesystem-write, or model capability is imported. The package self-identifies as device-local candidate human-outcome evidence and cannot upgrade synthetic regression results, unevaluated outcomes, or an incomplete sample into PMF proof. See [ADR 0021](decisions/0021-pilot-evidence-export-is-an-anonymous-reviewed-boundary.md).

`pilot-evidence-cohort.ts` is a research-side pure consumer, not a production-client import path. It treats every package as untrusted: exact schema/provenance, alias order, bounded values, task/output links, complete rubric, compiler ordering, and package size are revalidated, then every supplied summary is recomputed and compared. A cohort has 1–50 unique `participant-NNN` aliases and exactly one final package per participant; content-identical packages are rejected even when export dates differ. No stable cross-export person/run id is created, so a new final package replaces the participant's old manifest file rather than being incrementally merged.

Aggregate JSON/Markdown retains cohort summaries, task mix, weighted evaluation averages, the number-correctness gate, and a recurrence signal for distinct evaluated task dates within 28 days. It emits no participant alias, source package record, run/output alias, filename, path, or exact task date. The CLI reads only explicit relative regular files inside its manifest directory, rejects symlinks/path escape/oversize, prints without writing by default, and uses non-overwriting user-only files plus compensation when an output directory is supplied. Raw packages and reports are Git-ignored. This supports P1/P2 measurement without telemetry, identity, upload, or a hosted research database. See [ADR 0022](decisions/0022-pilot-cohorts-require-one-final-anonymous-package.md) and the [pilot runbook](pilot/README.md).

## Composable task runtime

Rune tasks are declarative product capabilities, not extra modal booleans inside the workbench. A task definition declares a stable id, the source capability it can accept, and the Artifact kinds it may consume. A short-lived task session records only explicit lifecycle facts (`awaiting-source → reviewing-source → configuring`) plus the captured workspace revision and exact imported Artifact identities. The runtime is a pure TypeScript module: it cannot import React, persistence, browser APIs, providers, or filesystem adapters.

Task execution has a second pure boundary. `task-providers.ts` is a static discriminated router from a registered task id and its typed input to the task's deterministic compiler. It owns no lifecycle, UI, storage, provider credential, or Apply authority. This keeps the workbench from importing every create compiler directly, gives tests one provider seam, and remains ordinary static TypeScript rather than a runtime plugin container.

Optional model shaping has a third narrow boundary. `task-model-planning.ts` accepts the same discriminated task identity plus an injected network function, then returns only validated task prose and planner metadata. It centralizes request lifecycle and bounded response handling without becoming another compiler or mutation layer. A new model-assisted task must extend its typed request/result union, exact source and size contract, evidence recomputation, and validator; it does not add another fetch state machine to the workbench.

The workbench is the assembly boundary. It may open the task-specific picker, run the existing import converter, present the existing atomic import review, and then pass the reviewed result back through the task runtime. The runtime proves the captured workspace revision, import-review identity, ordered imported ids, accepted Artifact kinds, and preferred source before the UI may continue. Only the existing import transaction writes the accepted source. Cancelling, choosing an incompatible file, changing the workspace, changing the reviewed import, or losing the preferred source closes the continuation without a task side effect.

This design takes four durable ideas from [Cordis](https://github.com/cordiverse/cordis) and [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): explicit lifecycle rather than implicit mounted state; declared capabilities rather than cross-module reach; pure components/geometry fed through narrow shares; and automated dependency-boundary checks. Rune deliberately does **not** add either repository as a runtime dependency, adopt Harness's chat/session shell, or introduce a dynamic plugin loader while the product is still proving its core Office tasks. Their plugin APIs are broader than Rune needs and currently carry avoidable migration cost. We use static typed composition first and keep the seam small enough to replace later.

Adding a task now has a bounded path:

1. Add its static definition and accepted Artifact kinds to the task registry.
2. Add pure phase transitions that capture exact revisions and identities.
3. Reuse an existing reviewed import/compiler/mutation capability; do not write from the task runtime.
4. Add one assembly entry in the workbench and one focused task surface.
5. If model shaping is useful, add one bounded server contract and one typed branch in the injected task-model port; return prose capabilities, never files or patches.
6. Extend the architecture gate so the runtime and client planning port still have no React, persistence, credential, or mutation dependency.

The first migrated path is operating review: Welcome or Empty workspace → choose CSV/JSON/XLSX/ODS → inspect the generated Data source → confirm one atomic import → map fields and deliverables with that exact imported Data source preselected. Independent multi-format Import and the existing manual operating-review entry remain available; they do not share hidden task state.

The second path is Document to Presentation. It creates a new collision-safe semantic HTML Presentation or selects a valid linked Presentation whose readable semantic metadata or compatible Deck `origin` resolves to the exact chosen Document. Refresh produces one source patch rather than another file: id, filename, Rune theme, origin, and existing HTML-or-Deck format remain stable while slides, title, language, audience, and purpose are recompiled from current reviewed input. Generated source carries bounded `audience` and `purpose` recipe fields beside title, language, and origin. Selecting a linked Presentation restores that source-owned recipe—including its output language—then opens the exact Document and refresh target directly. Older Decks without recipe fields retain parser and refresh compatibility; malformed recipe metadata invalidates the target. Rune does not persist a second browser-only briefing configuration that could drift from the portable file. Missing, wrong-kind, malformed, unrelated, no-op, stale, or downstream-invalid targets stop before review and leave checkpoints, persistence, and files unchanged.

Every task-generated Presentation additionally records `origin_revision`, a versioned, bounded FNV-1a 64-bit token over the exact UTF-8 bytes of the Document source used for that compile. `documentBriefingTargets` compares this source-owned baseline with a freshly derived token and returns exactly `current`, `changed`, or `unknown`; the file rail only calls attention to `changed`, while setup explains all three. A pre-v0.86 Deck without the optional field is `unknown` and remains refreshable; the next reviewed refresh records a baseline without changing its format. This token is an advisory change detector, not a cryptographic identity, integrity guarantee, security proof, or write capability. It never replaces exact Artifact ids, complete source revision capture, parser/runtime validation, transaction review, checkpointing, or Apply-time equality checks.

The changed-state affordance is an orchestration shortcut, not another mutation surface. It receives the clicked exact Presentation id, resolves that Artifact again from the current workspace ref, re-parses its exact Document origin, recalculates freshness from current sources, and stops if the relationship is no longer changed. A valid action selects the Presentation and opens the same `configuring` task session with its source-owned recipe and target id. It calls no compiler, persistence adapter, or artifact state setter. All busy/review states share the existing creation-disable contract. The normal file-row button still opens the Artifact, while a separate keyboard-focusable refresh control occupies logical inline-end below the context pin; both position and reserved padding mirror under RTL.

## Security boundaries

- Markdown is rendered as React elements and does not execute embedded HTML.
- Deck Markdown rejects raw HTML, validates layout metadata, and escapes user text before entering a restrictive no-script iframe; semantic HTML receives only compiler-proven exact-section source editing inside the sandboxed compatibility path, never rendered-DOM write authority.
- CSV and JSON parsing is local and must expose validation errors rather than guessing silently.
- SQL runs in a dedicated browser worker; an optional first-line quoted Data directive is identity-resolved before execution, the preview accepts one read-only query, bounds visible results to 500 rows, and grants result targets only to a compiler-proven one-table row-preserving subset with safe hidden ids and unique direct columns. Query-backed charts require a current non-truncated snapshot of that same resolved Data revision; Query-backed scalar metrics additionally require exactly one row, one unambiguous output cell, and a finite numeric value. Static output inference never grants runtime value or provenance.
- Chart JSON is strict and code-free; only bar/line/area marks and bounded finite points are accepted, and text is React-escaped or HTML/XML/PDF-sanitized before preview and export rendering.
- Agent provider output contains only bounded discriminated patch/create actions and source operations. It cannot author creation identity, filenames, extensions, language metadata, complete source, or state writes. Keyed Data-column updates cannot modify their key or insert rows; new columns require complete current-row coverage; renames reject missing, multiline, whitespace-padded, unchanged, or colliding headers. Artifact/template mismatch, missing or ambiguous heading/key/title, duplicate key/cell, nested JSON, Deck separator injection, repeated-file, identity collision, cancelling, oversized, stale-revision, or downstream-invalid plans produce no workspace write.
- Workspace model context contains only upstream-closed components rooted at the selected artifact or at most six session-only user pins within seven-file/180,000-character limits; the server recompiles every dependency, rejects unpinned disconnected padding, and the full client workspace remains the final validation and revision boundary.
- Query evidence is accepted only in verified Workspace scope after the server confirms a configured provider, is bounded by rows/columns/cells/string and total JSON size, must match every Query and resolved Data identity in exact order, is labelled for truncation/error, and is never persisted or granted write authority. Evidence cell, column, and error strings are explicitly untrusted data rather than model instructions. Because the pack is client-computed rather than attested, canonical source and deterministic compilers remain the authority.
- Every Agent-authored Data, Query, or Chart source enters a local proposed-workspace impact gate before review. Rune executes only directly changed Queries, Queries bound to changed Data, and exact Query sources selected by changed/new Charts, then validates affected legacy metrics, Query scalars, direct-Data Charts, and Query-backed Charts from the same proposed revisions. Any Data parse/value, SQL, cardinality, type, truncation, schema, or Chart-value failure creates no pending mutation and writes no history or state; disconnected new Data and direct-Data Charts never broaden SQL execution.
- A configured provider receives at most one automatic repair request after its first unapplied proposal fails that impact gate. Feedback contains only 1–4 identity-checked proposed sources plus a normalized 1,000-character failure within the existing source budgets, is labelled untrusted, and retains no write authority. A replacement is accepted only with the exact attempt marker and after server compilation plus a second complete local impact proof; any failure stops without recursive retry or deterministic fallback.
- Selection Agent requests bind non-empty UTF-16 offsets to one exact source revision, reject surrogate-splitting or oversized ranges, and require the server compiler and client Apply path to independently prove that source outside the selection is unchanged.
- Preview targets are locally derived from the current canonical revision and only populate that existing selection contract; Markdown fragment syntax and delimiters, CSV quotes, and JSON value delimiters stay inside exact ranges, while Chart-bearing fragments and empty/ambiguous data tokens receive no competing capability. The reverse link also starts from current UTF-16 source offsets, chooses the smallest containing proven range (Document fragment before block before section, Data cell before row), and uses DOM only to scroll the already-proven id into view. Rendered DOM, sandbox contents, labels, and indices never become write authority, and derived views without exact source provenance remain non-targetable.
- Controlled preview editors may project an unsaved input into a complete source mirror only through their existing revision-bound compiler. The mirror carries exact replacement offsets and validation errors, is read-only in the canonical pane, never enters artifact state, persistence, history, exports, folder sync, dependencies, or Agent context, and is discarded on Cancel. Save recompiles from the unchanged base artifact, then uses the normal whole-workspace/runtime/checkpoint gate; the mirror itself has no write authority.
- Document structure operations re-resolve the full block identity against the current CommonMark/GFM AST. Insert accepts exactly one supported block and cannot mint live bindings; move swaps only adjacent supported siblings while preserving their bytes and intervening whitespace; delete refuses the final block and removes a proven adjacent separator. Every proposed source is shown in a modal diff, then recompiled byte-for-byte at confirmation before workspace validation, checkpoint, and one persistence write. Unsupported top-level nodes, ambiguous gaps, stale targets, heading/body ambiguity, cancellation, and storage failure grant no write.
- Bar and line marks retain compiler-owned provenance through sorting, truncation, and line normalization, then resolve direct Data or direct Query-projected fields against current canonical cell targets; derived Query fields remain read-only, and cross-artifact targeting never matches by a duplicate label, visible order, formatted value, or DOM/SVG geometry.
- Creation accepts bounded single-line titles plus exact typed Query/Chart bindings; generated identity is portable and collision-safe, optional Chart embedding checkpoints its consumer, the complete next workspace and runtime impact validate before persistence, and a failed device write leaves React state unchanged.
- OOXML import rejects oversized/unsafe ZIP parts, path traversal, DTD/entity declarations, invalid output adapters, and partial device writes; binary input never leaves the browser.
- OpenDocument import additionally requires an extension-matched root MIME declaration and an uncompressed first `mimetype` ZIP entry, rejects encryption and duplicate paths, ignores scripts/macros and signatures, bounds repeated spreadsheet extents without expanding empty rows or columns, and encodes binding braces before canonical validation.
- PDF import requires bounded local bytes and a valid header, disables eval and remote PDF fetching, refuses passwords, encodes binding braces, caps pages/fragments/rendered pixels/output, ignores document JavaScript, and exposes every extraction loss before the shared import confirmation. Scan OCR additionally requires an exact detected-page selection and language choice, reads no pixels until explicit preview or recognition, validates optional per-page normalized regions before cropping, uses bundled same-origin worker/core/language assets, labels page provenance plus confidence and crop, supports stop-without-write, and cannot run over selectable or missing pages.
- Import confirmation rejects stale workspace context and keeps quota failures inside the open review instead of partially updating React or device state.
- Office export sanitizes XML characters, restricts hyperlink schemes, writes spreadsheet text as values rather than formulas, resolves Query metric and chart snapshots only through validated workspace artifacts, rejects stale review context, and caps generated package bytes.
- OpenDocument export emits deterministic ODF 1.3 packages with restricted HTTP/HTTPS/mailto links and no scripts, formulas, external media dependencies, or live bindings; exact MIME/manifest structure, official Relax NG validation, revision-bound snapshots, stale review rejection, and package caps are required before handoff.
- Standalone HTML export requires every legacy metric, Query metric, and chart binding to resolve from current revisions, escapes user content, rejects executable or external-resource elements and attributes after rendering, checks stale review context, and caps final UTF-8 bytes.
- PDF export accepts only validated Markdown Documents, compiler-proven semantic HTML Presentations, or compatible Deck Markdown; semantic HTML uses the immutable controlled projection, every metric and chart resolves against current revisions, the same-origin WOFF2 asset is validated, unsupported glyphs stay visible, metadata is fixed, no JavaScript/forms/external resources are emitted, stale review context is rejected, and source/font/final bytes are capped.
- Folder manifests reject hidden/path-like names, duplicate identity, missing sources, oversized payloads, and invalid dependency graphs before Pull.
- Provider keys belong in server-side secrets; they are never committed or stored in browser drafts.
- XLSX import reads cached formula values and prefixes formula-leading text with an apostrophe before it becomes CSV; future generated CSV/XLSX export must reuse this injection boundary.

## Evolution path

### Interface design-system boundary

Rune treats interface architecture as a stable product contract rather than a growing cascade of component exceptions. `app/globals.css` is now a frozen compatibility layer for the existing inventory; all new design-system authority loads once from `app/styles/index.css` in this dependency order: tokens, shell, content, overlays, onboarding, motion, responsive. Tokens own the spacing/type/curve/content-width/motion scales and the only numeric layer map. Shell may place the top bar, rails and panes; content may style canonical source and compiled output; overlays may place menus and modal surfaces but cannot change page layout; onboarding owns only setup; motion cannot define geometry; responsive may adapt existing semantics but cannot invent a parallel component design.

The root layer order is canvas → workspace → status → pane disclosure → top bar → global float → blocking modal → onboarding. Every module other than tokens consumes semantic `--rune-layer-*` values; numeric `z-index` values are forbidden there. The app shell deliberately avoids `isolation` and overflow clipping, the top bar and pane headers expose their overlay anchors, and every viewport-bound popover has a maximum block size plus its own scrolling. Structural entry animations use `animation-fill-mode: backwards`, so their finished transforms do not remain as accidental stacking contexts. A future portal root may replace top-bar containment without changing the layer contract.

The geometry follows a content-first baseline informed by ColaMD without copying its product shape: compiled prose stays at 780px with 16–16.5px text and approximately 1.72–1.75 line height, while the workflow rail settles at 220px. Rune retains the simultaneous source/preview workspace that ColaMD does not need. Appearance shows one named current material and a compact swatch strip; locale names remain in accessible labels rather than forcing nine long localized names into a small popover. The welcome primary action sits inside the language decision surface, preventing a detached control from colliding with short-height content.

`tests/design-system-architecture.test.mjs` enforces module order, single-source layer authority, unclipped overlay anchors, tier relationships, the content geometry, and welcome-action placement. New UI work must extend these semantic modules and tests instead of appending a versioned “cascade seal.”

### Workspace presentation state

The source/preview ratio and the `split | source | preview` focus mode are bounded device-local presentation preferences. On desktop, both panes remain mounted while compatible grid tracks move between their bounded split and zero width over 240ms. The hidden pane is `inert`, `aria-hidden`, invisible, and non-interactive, so selection, scroll, preview runtime, and undo context remain available without exposing off-screen focus targets. Drag resizing bypasses easing and reduced-motion collapses the transition. Canonical source, revision-bound visual drafts, preview targets, checkpoints, dependency state, folder manifests, Agent context, and exports never read these preferences. Opening a proven preview target while Source is hidden restores Split before applying the exact canonical selection; returning from Source to a preview-capable mode replays scrolling from the retained parser-derived target identity. This adopts the mounted-panel interaction principle documented in the [DeepSeek Harness review](references/deepseek-harness-ui-architecture-review.md) without importing its runtime.

The shared shortcut resolver accepts only `Meta/Control + Alt + physical Digit1/2/3`, rejects Shift and other keys, and is reused by both onboarding practice and the workbench. The workbench suppresses this presentation action while any modal review, import/export, model setup, pending Agent proposal, or revision-bound visual draft owns interaction. Controls expose the same contract through localized labels and `aria-keyshortcuts`.

Preview provenance uses progressive disclosure only at the presentation boundary. The always-visible summary is derived from the current validation error count; its native details body renders the same current source target, exact Data/Query source, metric/Chart binding counts, and validation result that previously occupied the header. It owns no copied evidence state, has no influence on compilation or permissions, and retains native keyboard semantics plus RTL/mobile placement.

Preview repair guidance has a separate React-free contract. `artifact-diagnostics.ts` receives parser/compiler/binding facts already derived by their domain owners, classifies them into stable source/metric/Query/Chart codes, deduplicates them, and bounds count, detail, and optional reference before returning an immutable snapshot. It cannot translate, render, fetch, persist, call a provider, or mutate source. The Workbench is the assembly and effect boundary: it supplies current facts, maps codes to the complete nine-locale UI catalog, and exposes one explicit action that restores Split when necessary, focuses the canonical Source textarea, and selects/centers an exact missing reference when it still exists. Raw compiler detail remains unchanged behind an optional native disclosure. No diagnostic can authorize an automatic repair, Agent request, checkpoint, or workspace write. See [ADR 0025](decisions/0025-preview-diagnostics-separate-facts-copy-and-actions.md).

Top-bar disclosure is likewise presentation-only. Review creation, artifact creation, import, and contextual export remain direct task actions. Help/onboarding, model setup, directory connect/Pull/Push, and appearance reuse their existing handlers from one localized menu; appearance choices remain twelve explicit `menuitemradio` controls. Each named theme maps a device-finish swatch to a separate contrast-safe interface accent, while the persisted id and Rune vermilion brand mark stay independent. The More Tools and Export surfaces are mutually exclusive and share outside-click/Escape dismissal, but neither menu owns command, credential, directory, or artifact state.

Localized geometry is a release contract rather than a collection of locale-specific overrides. The same welcome, empty-workspace, topbar, rail, statusbar, and workbench components must remain bounded for all nine registered locales at desktop and compact viewports, with Arabic using the same logical layout under RTL. The selected welcome language is programmatically revealed inside its own scroll surface; long status copy is clipped within its grid owner instead of widening the shell. Browser tests enforce viewport containment, welcome component separation, touch-target height, RTL direction, and zero document overflow. These presentation effects cannot read or mutate canonical Artifact state.

Desktop workspace material is a CSS-only continuous surface: activity/file rails, source, separator, and preview keep their component, scroll, aria, and revision boundaries, while adjacent borders/gaps/shadows collapse and only physical outer panes own corner radii. Focus modes transfer the trailing radius to the last visible pane, and RTL mirrors physical edges. At 960px and below, panes recover independent borders, radii, shadows, and spacing for the existing stacked document flow.

Source header disclosure reuses the existing `historyOpen` boolean and checkpoint panel rather than introducing another version model. Its summary combines the selected artifact's language and current checkpoint count; the panel adds the unchanged nearest-different undo handler beside manual checkpoint save and exact checkpoint restore. All enablement still derives from current source equality and visual-draft locks, and only the presentation/placement changes.

Status-bar simplification is presentation-only. The left side continues to render the existing bounded `visibleNotice`; the right side derives artifact statistics directly from the selected canonical source. Encoding, binding counts, validation evidence, and product version are not copied into new state: provenance remains in the Preview disclosure, while the static version moves to the More Tools footer. This keeps the bottom edge task-focused without weakening any validation or source contract.

Assistance chrome is likewise presentation-only. The source-integrated composer, existing three-way scope setter, planner-status badge, and native suggestions disclosure all read the same prompt, selection, dependency context, provider mode, and Query-evidence count. Suggested commands still call the same `runAgent` boundary, while a pending mutation continues to expand the complete patch/runtime/transaction review above the composer. Removing the persistent avatar/title card and collapsing idle suggestions does not alter context authority, runtime gates, checkpoints, or Apply/Discard behavior.

### Agent proposal projection

A valid pending Agent mutation owns an ephemeral, complete candidate workspace derived by the same `prepareWorkspaceMutation` gate used before Apply. `prepareWorkspaceProposalPreview` is a pure projection: it first requires the exact captured source revision, then prepares all patches and creations atomically, and returns either the complete proposed artifact array or no candidate at all. It never persists, checkpoints, fetches, exports, or mutates its caller's artifacts. New identities are visible only inside the projection until Apply.

`prepareWorkspaceProposalSurface` is the React-free presentation adapter over that projection. It derives review-active state, candidate-active state, the one artifact shown in Source, and the complete artifact array passed to Preview in one immutable result. The Workbench must not independently assemble those values. An absent proposal returns the canonical selection and workspace; an invalid or stale proposal keeps review active but returns the same canonical fallback to both panes, so no partial proposal can create a split-brain review. See [ADR 0048](decisions/0048-agent-review-uses-one-candidate-workspace-surface.md).

The workbench may present any artifact from that candidate workspace, not only a changed node. The source pane shows that artifact's complete proposed source read-only; the preview receives the complete proposed workspace so Query results, scalar metrics, Chart models, Documents, and Decks compile against the same transaction. This is especially important for an unchanged downstream deliverable: its source can remain byte-identical while its rendered values change because an upstream Data, Query, or Chart proposal changed. Transaction-map and file-rail selection only choose which candidate artifact to inspect; they grant no new edit capability.

Proposal projection is presentation state, not an optimistic write. Preview-to-source targeting and every visual edit callback are disabled while it is active, and the canonical source revision continues to own Agent context, checkpoints, local persistence, directory Push, and export. Apply and Discard are the only state transitions out of review. Apply repeats revision and whole-workspace validation before the existing single persistence transaction; Discard destroys the projection. A stale revision, duplicate/unknown patch, invalid creation, broken binding, or other mutation error fails closed and cannot expose a partially prepared workspace.

File-rail workflow grouping is a render-time projection over the canonical `WorkspaceArtifact[]`: Data maps to Sources, Query/Chart to Analysis, and Document/Slides to Deliverables, preserving the original array order inside each group. Group ids are presentation constants rather than persisted folders or graph nodes. Selection, temporary pins, context closure, revisions, directory manifests, and exports continue to resolve exact artifact ids; semantic sections and localized headings only improve navigation hierarchy.

Top-bar simplification reuses existing handlers and state. New, Import, Export, and More Tools remain global controls; operating-review creation retains the same handler in the persistent activity rail rather than rendering a duplicate top-bar button. The compact `role="status"` save indicator derives its accessible label and title from existing save state, timestamp, and localized copy. Workspace identity still reads the directory handle or local-workspace label; no navigation, persistence, task, or save model changes.

The full-screen Setup Assistant is a presentation change over the existing `WelcomeExperience` state machine. `welcome | model | shortcuts | ready`, locale detection/selection, provider status, local fallback, real shortcut capture, dismissibility, and completion actions are unchanged. Within `welcome`, one derived `writing | ready` presentation phase first hides and unfocuses setup chrome, lifts the handwritten greeting into the optical center, and keeps the background nearly neutral; the final ink settle then returns the greeting to the stable grid while chrome, copy, and language controls unfold. A bounded timeout remains only an animation-event fallback, and reduced motion resolves immediately. The viewport-sized shell supplies one chrome row plus a scrolling page; the step strip exposes `progressbar` min/max/current values. No onboarding state enters Artifact, workspace persistence, model credentials, or export state beyond the already explicit completion choices.

The animated opening word is a separate props-only `HandwrittenGreeting` presentation boundary. `WelcomeExperience` remains the owner of greeting order, locale choice, adaptive cycle timing, and the onboarding transition; the child receives only one value, one locale, and one duration. It renders original inline SVG text from the current system writing face through an ordered collection of writing-system-aware path masks, a nine-stop spectrum fill, deterministic paper-ink displacement, clipped wet trails and dry-brush bristles, and a small pressure-lit split nib whose path and clock are identical to the active mask. After the final settle, one narrow highlight rectangle crosses a clip made from the same complete shaped text and stops; it cannot spill outside the glyphs, loop, alter timing, or become a pointer. Script-aware view boxes control optical width; Arabic is never split into graphemes and keeps one RTL shaping run. There is no independent flourish, whole-word wipe, particle field, remote font, or copied Apple asset. The component has no timer, browser storage, network, provider, credential, Artifact, or mutation dependency. Reduced motion completes every mask, hides transient ink layers, and shows the final fill immediately; forced colors uses `CanvasText`. See [ADR 0033](decisions/0033-welcome-writing-is-an-isolated-svg-presentation.md), [ADR 0038](decisions/0038-welcome-ink-follows-one-directional-mask.md), [ADR 0040](decisions/0040-welcome-ink-is-scheduled-by-writing-system.md), and [ADR 0042](decisions/0042-welcome-ink-settles-with-one-calligraphic-sheen.md).

Low-frequency interaction surfaces cross a typed on-demand boundary. Welcome, Quick Actions, transaction lineage, OCR setup, and create/import/export/task review dialogs are same-origin static `React.lazy` entries; `RuneWorkbench` remains their sole state, review, persistence, and mutation owner. Localized `Suspense` fallbacks are non-mutating status presentation with distinct welcome, blocking-overlay, and inline geometry. Eager notices consume a small React-free `workbench-surface-copy` port shared with deferred dialogs, and the locale catalog generator scans its English base objects explicitly. Manifest tests require all thirteen dynamic entries and cap the minified Workbench at 530 KB; source tests reject static runtime import regressions. See [ADR 0034](decisions/0034-low-frequency-surfaces-load-on-demand.md).

Welcome writing timing is prepared by the React-free `greeting-motion.ts` boundary. It receives only finite presentation inputs and returns frozen ordered strokes containing a bounded SVG path, brush width, delay, and duration plus the single final settle time. Latin/Cyrillic, logographic, kana, Hangul, and Arabic strategies make pen lifts and joins perceptible without splitting the final SVG shaping run; RTL visible non-mark symbol count still controls Arabic timing. `HandwrittenGreeting` translates that plan into per-stroke CSS custom properties, and every moving ink head reuses the exact mask path and clock so visual feedback cannot drift. The completion sheen is derived only from the already-computed settle time and canvas width; it adds no scheduler, DOM measurement, Canvas, locale loading, persistence, provider, credential, or workspace dependency. Reduced-motion and forced-color fallbacks remove every transient layer. See [ADR 0035](decisions/0035-greeting-motion-is-planned-before-animation.md), [ADR 0038](decisions/0038-welcome-ink-follows-one-directional-mask.md), [ADR 0040](decisions/0040-welcome-ink-is-scheduled-by-writing-system.md), and [ADR 0042](decisions/0042-welcome-ink-settles-with-one-calligraphic-sheen.md).

Preview lineage relocation moves the existing render branches into the existing native evidence disclosure. Chart source, Query/Data resolution, Query scalar references, legacy metric references, and embedded Chart ids continue to derive synchronously from the selected artifact and current workspace; the same localized status text is rendered. The default preview body now owns only the compiled-output scroll container. No lineage snapshot, validation cache, alternate identity, or permission path is introduced.

Device-local Document and Deck images use one strict `rune-asset:sha256:<64 lowercase hex>` source contract. PNG/JPEG/WebP/GIF bytes are magic-byte validated, capped at 8 MB each, hashed before review, and stored in an IndexedDB object store capped at 40 records/64 MB. The canonical Markdown contains only the content-hash reference and required alt text; it never contains base64. Preview resolution rereads the blob, repeats size/format/hash validation, creates an ephemeral object URL, and revokes replaced URLs. Missing or corrupt bytes fail closed.

Image insertion is revision-bound and review-before-write. Rune stores/deduplicates the asset first, persists the validated next workspace and pre-write checkpoint second, and removes a newly created asset when source persistence fails. Existing deduplicated bytes are never deleted by compensation. A Deck insertion must be inside one proven slide range and the complete next Deck must parse before review or write. The Deck grammar accepts one standalone local image on a non-`metrics` slide and treats image, Chart, and table as mutually exclusive primary visuals. The same verified bytes flow through directory sync, live preview, PPTX media relationships, ODP picture manifests, standalone HTML data URLs, and PDF image objects; no adapter owns a second identity or asset database. Raw source download intentionally carries only the portable reference. Hosted R2 remains undeclared.

## Quality gates

### Presentation default boundary

Fixtures must prove the sample, New, Operating Review, Document-to-Presentation, configured Agent, deterministic Agent, and PPTX/ODP import all create `.html` with the same `presentation-v1` main metadata and outer-section contract. Agent HTML replace/insert and Chart append must use exact compiler-proven indices, preserve unaffected source, and reindex only Rune-owned pages. Refresh must preserve an existing semantic-HTML-or-Deck format. Case-insensitive identity collisions must keep id and filename suffixes aligned. Real-media PPTX/ODP round trips must retain exact verified bytes, one readable hash reference, one-primary-visual limits, atomic source/asset review, and zero escaped placeholders. Preview must accept only approved blob resolution; standalone HTML must embed only reviewed data URLs and reject every active/external boundary. Office, OpenDocument, and PDF handoff from semantic HTML must prove the temporary projection does not mutate canonical source.

The production-dependency audit (`npm run audit:production`) is a release gate alongside the build, typecheck, lint, test suite, and synthetic Golden Task Eval. GitHub runs that same sequence on main and pull requests.

### Static human-command seam

`workbench-commands.ts` is the definition side of Rune's human-command seam. It owns stable command ids, grouping, localized presentation copy, keywords, shortcuts, deterministic ranking, and capability-derived availability. `WorkbenchCommandMenu` is a presentation-only consumer: it owns query state, keyboard navigation, focus restoration, and an `onRun(id)` event, but cannot import persistence, Artifact mutation, providers, or fetch. `RuneWorkbench` remains the composition and execution boundary and dispatches each id to its existing capability owner. This adopts DeepSeek Harness's command/service separation without adding a runtime plugin tree before Rune has real unload or third-party composition requirements.

### Golden Task evidence boundary

`evals/` is development evidence and is never imported by the production client. Versioned synthetic fixtures enter the same public task-provider, transaction, parser, and DuckDB-Wasm seams as the product. The runner freezes inputs, proves expected success or zero-output rejection, applies the ordinary whole-workspace gate, executes ten generated Queries, and checks Chart/live-deliverable or Document-origin contracts. `evals/BASELINE.md` is deterministic and checked on every `npm test`.

Synthetic tasks are evidence grade E1 only. They can prove deterministic regression behavior but cannot prove demand, usability, time saved, delivery, retention, or payment. Human outcome scoring stays empty until an authorized licensed or redacted task is reviewed on the seven product-plan dimensions; number correctness below 4 cannot be hidden by averaging. The real-pilot threshold remains twenty tasks.

### Human outcome evidence boundary

`task-evidence.ts` owns one versioned, content-free device ledger for both focused tasks. Storage v3 migrates valid v1/v2 runs and quick delivery outcomes without inventing detailed scores; delivery v2 adds either a fully normalized `RuneTaskHumanEvaluation` or `null`. The evaluator has exactly seven static dimensions and integer scores from 1 through 5. A detailed object is valid only when all keys are present, no foreign key is present, and provenance is the literal `authorized-or-redacted`. Malformed detail fails closed to `null` during untrusted storage normalization and is rejected when explicitly submitted by a caller.

The shared delivery dialog is only a UI consumer. Its default path emits the existing quick rating. A progressive disclosure owns temporary rubric state, leaves every score blank, and cannot confirm until all seven values plus the authorization/redaction assertion exist. The Workbench passes that typed confirmation into the same exact-run/all-output revision gate; it does not own rubric validation or summary math. Quick reconfirmation preserves a prior detailed evaluation, while explicit `null` remains the only clearing operation.

Summaries distinguish evaluated deliverables from unique reviewed task runs. Pilot eligibility is computed per run and requires every evaluated deliverable in that run to have number correctness of at least 4. The below-four count and per-record number score remain visible independently of dimension averages. No source, prompt, provider response, Query row, filename as measurement, credential, user identity, or telemetry enters this ledger, and no evaluator submission is manufactured by tests or release code.
