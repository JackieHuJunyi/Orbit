Rune v0.83 proves the static task seam with a second real outcome: onboarding, an empty workspace, or an existing Document can turn reviewed Markdown, Word, ODT, or PDF source into 4/6/8 editable Deck Markdown slides, then use the existing HTML/PPTX/ODP/PDF exports. The generated Deck records an exact `origin` Document id, so the dependency graph and transaction review show `Document → Presentation` and reject an unresolved origin before any write. Scanned PDF continues through the same explicit on-device OCR selection and import review before task setup. All new task surfaces are covered across the nine interface locales. See [ADR 0001](docs/decisions/0001-composable-task-runtime.md) and [ADR 0002](docs/decisions/0002-source-linked-task-providers.md).

Rune v0.82 made the first operating-review path outcome-first: onboarding or an empty workspace can choose CSV/JSON/XLSX/ODS, inspect the unchanged atomic import review, and continue directly into field/deliverable mapping with the exact imported Data identity preselected. The pure static task runtime owns the explicit `awaiting-source → reviewing-source → configuring` lifecycle and revision checks; React, browser APIs, providers, and persistence remain outside that module. The architecture is informed by Cordis and DeepSeek Harness, without adopting their broader dynamic plugin/session shell before Rune has demonstrated that cost is necessary.
